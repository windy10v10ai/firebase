# 本机专用服启动器

玩家双击运行的 Windows 小程序 `Windy10v10AI.exe`：在本机单独开一个专用服再连进去，服务器和客户端分到不同核心，缓解后期卡顿。可以单人玩，也可以开联机主机让朋友凭房间码加入。

## 做了什么

1. 找到 Steam 里的 Dota 2 和已订阅的地图，检查地图是否最新。
2. 在后台启动专用服，等地图加载完成。
3. 通过 Steam 启动 Dota 2 并自动连进去；单人游戏在 Dota 2 退出后关闭专用服，联机主机的专用服见「联机」。

客户端用注册表记录的 Steam 客户端配合 `-applaunch` 启动，兼容 `steam.exe` 与 `steamchina.exe`：直接运行 `dota2.exe` 会跳过 Steam 的会话验证，打完一局不退出 Dota 再从游廊开局时被 VAC 拦下；没用 `steam://run`，因为带参数时会弹 Steam 确认框。

每次打开时查一次有没有新版本，有就在提示条上给出「更新」按钮，点击后下载、替换自己并重启。

联网行为、对电脑的改动与卸载方式见[代码签名政策](https://windy10v10ai.com/launch/code-signing)。

## 不修改 Dota 2 文件

启动器不改 Dota 2 原有的任何文件，也不注入或读写 Dota 进程。它只新增地图目录 `game/dota_addons/<地图ID>/`（工坊地图文件的硬链接）、专用服日志和客户端日志。

所以不采用 A2S 方案：它能让已开着的 Dota 直接连进重开的专用服，但要改玩家的 `gameinfo.gi`，有触发反作弊握手失败的风险。再开一局仍需先关闭 Dota。

## 联机

顶部分段切换「单人游戏 | 联机主机 | 加入联机」。设计与取舍见[阶段 1 设计](../docs/design/launcher-multiplayer/phase-1-friend-room.md)、[阶段 2 设计](../docs/design/launcher-multiplayer/phase-2-public-room.md)、[阶段 3 设计](../docs/design/launcher-multiplayer/phase-3-room-flow.md)与[阶段 4 设计](../docs/design/launcher-multiplayer/phase-4-relay.md)。

- **Dota 两边都只连本机**：跨网的只有两个启动器之间的 UDP 隧道，单人模式验证过的 Dota 行为不变。
- **API 只牵线**：开房、轮询、交换双方地址走 API；直连时游戏数据不经过我们的服务器。
- **不依赖公网 IP**：局域网、STUN 打洞、中转三条路同时试，按局域网 > 打洞 > 中转取用，中转先通也等到握手开始后 3 秒；不用 UPnP，理由见设计文档。选路由加入者决定再告诉房主。
- **中转只转发、不看内容**：服务器在 server 仓库，国内一台。每次加入在中转上分一个单独的端口，房主照旧按对方地址区分朋友。中转地址与通行证由 API 下发，API 不配地址时不走中转；加入者带 `--relay-only` 启动只走中转，用来实测。
- **玩家列表由房主维护**：房主从隧道与专用服日志得知每个人的状态，经隧道发给加入者，两边看到的一致。状态只有连接中、已连通正在载入、已进入游戏、连接失败、已离开五种，不跟踪 Dota 内的掉线与重连。
- **联机要求地图最新**：双方地图版本不同进游戏可能出错，地图不是最新时联机两个分段都不能开局。
- **联机主机关闭自动开始**：专用服带固定的服务器名启动，游戏据此等房主点「锁定并开始」。
- **开房前说明游戏会在 Dota 2 里等人**：联机主机页空闲时用绿色提示条代替状态行，告诉主机 Dota 2 会自动打开、人齐后在 Dota 2 里点「锁定并开始」。开房后 Dota 2 全屏，启动器上的提示看不到。
- **公开房间不突出房间码**：公开房间的房间码是一行灰色小字、没有「复制」，好友房保持醒目的房间码框。
- **联机的专用服只由主机关闭**：主机关掉 Dota 2 时服务器继续跑，可以「重新进入游戏」；唯一的自动关闭是结算保存完、主机与所有加入者都已退出 Dota 2。结算保存期间点「关闭服务器」要确认。
- **被服务器断开也能「重新进入游戏」**：启动器读 Dota 日志里的断线原因，玩家自己退出以外的断线都显示橙色「重新进入游戏」，单人游戏也一样，只有关掉 Dota 2 才算结束单人游戏。Dota 被断开后仍开着、不认第二次启动，所以重新进入会先关掉它。
- **专用服用「高于正常」优先级**：主机自己的 Dota 2 在同一台电脑上渲染，服务器被抢走 CPU 时所有人的连接一起卡顿甚至溢出断线。
- **开房与加入要先等 Steam 登录**：房间按 Steam 账号区分玩家，Steam 没开时先启动它并等登录完成再向 API 报到。
- **选队界面的进入名单由主机启动器在本机提供**：联机主机开房期间在 `127.0.0.1:27080/room` 返回还在连接、载入的玩家，以及已进入游戏的人数（含主机）与人数上限，只绑本机。游戏在选队阶段读它显示房间状态条，端口两边约定，改动要同步 game 仓库；读不到时游戏不显示这条。
- **游戏结束由主机读日志转告**：主机从专用服日志判断游戏结束（结算请求发出或进入结束阶段）与结算完成（游戏打印的结算回调；离线局没有这一行，结束 2 分钟后视为完成），再经隧道告诉加入者。加入者关掉 Dota 2 后自动退出房间，主机关服务器也只显示「游戏已结束」。启动器从不关闭 Dota 2。
- **房间默认公开**：公开房间进「加入联机」页的列表，好友房不进列表，只能凭房间码加入；房主开房后仍可改类型与人数上限。
- **列表延迟是实测的**：对列表里每个房间先打一次洞量往返时间，用三格信号表示；打不通的房间排在后面、仍可加入，加入时由中转接上；它的延迟是估算的：自己到中转的往返加上房主报来的房主到中转的往返，房主没测到时按自己的翻倍。测试用的端口就是之后加入用的端口，点「加入」时房主已认得这个地址。到中转的测量连发 20 次回声，往返与丢包随加入请求和房主轮询带给 API 写进统计，不单独发请求，用来看各地到中转的线路好坏。
- **标题显示正在进行的联机**：只显示仍有心跳的公开游戏局数与玩家数，不显示不能加入的房间资料。
- **房主可以移出玩家**：被移出的人这一局进不来这个房间，房主重新开房就清空，不做跨房间的黑名单。
- **开房 15 分钟没开局就关闭房间**：停止轮询，房间从列表消失、凭码也进不来，房主自己的游戏不受影响；房主点「重新开放」恢复，房间码不变。
- **本机只存界面选择与头像**：上次的分段、房间类型、人数上限与 Steam 头像缓存放 `%LocalAppData%\Windy10v10AI\`，读写失败一律忽略，不用注册表。

## 自我更新

- **版本信息与下载都走 API**：国内代理只转发 `/api/`，大陆玩家先直连、失败再走代理，和地图检测同一套路线。
- **只校验 sha256，不做代码签名**：发版只有维护者本人能部署，哈希用来挡下载不完整或被代理损坏；以后要加签名，旧版会先自动更新到带公钥的版本，不需要玩家手动下载。
- **只升不降**：线上版本比自己新才提示，本地开发时把版本号定得比线上高，不会被换回旧版。
- 封闭测试版（`build.cmd beta`）不检查更新。

## 编译

```bat
launcher\build.cmd
```

产物在 `launcher/dist/Windy10v10AI.exe`。只依赖 Windows 自带的 .NET Framework 4 编译器，源码只能用 C# 5 语法。

## 发布

exe 放在官网 `/launch` 下载页，只从 `develop` 编译，每次发版分两个 PR：

1. 代码 PR：当前版本号已经发布过时，升 `src/Launcher.cs` 的 `Version`、`AssemblyVersion` 与 `AssemblyFileVersion`（规则见 [CLAUDE.md](CLAUDE.md) 的「版本号」），合进 `develop`。可以攒几个 PR 再发版，攒着的这几个共用同一个未发布的版本号。
2. 在 `develop` 上运行「Launcher release build」工作流（`gh workflow run launcher-release.yml --ref develop`），下载产物（`gh run download <run-id>`）。其他分支、或版本号不比线上新时会直接失败。发布的 exe 必须来自这里，不用本机编译的。
3. 代码签名下来之前，每次发版都用本机 Defender 扫描这个 exe，必须没有报毒：Defender 报毒时玩家一下载就被隔离。再上传到 [VirusTotal](https://www.virustotal.com/)，两项结果都写进发版 PR 的测试清单，其他引擎零星报毒可以接受。VirusTotal 的 Microsoft 一栏是云端机器学习判定（名字带 `!ml`），同一份代码重新编译都可能翻转，与本机 Defender 不一致时以本机为准，到 [Microsoft 误报申报页](https://www.microsoft.com/en-us/wdsi/filesubmission) 提交这个 exe 后即可发版；报的是具体病毒家族名、或大量引擎一起报时先停下排查。
4. 发版 PR：
   - 把 exe 复制为 `web/public/downloads/Windy10v10AI-<version>.exe`，删掉旧版。
   - 改 `web/app/launch/launcher.ts` 的 `LAUNCHER_VERSION`。
   - 改 `api/src/launcher/launcher-release.service.ts` 的版本号与 sha256（运行摘要里有）。抄错时 api 单测会失败。
   - 在官网 `/launch` 的更新日志加本版条目（`web/app/launch/changelog.ts` 与三语 `launch.changelog.entries`）。只单独列对玩家影响大的主要变化，其余小修小改合成一句「修复了一些问题，优化了使用体验」，不逐条写技术细节；跳过未发布的版本，它们的改动并进本版；只有小修小改、写不出实质内容的版本不列条目。启动器右上角的版本号链接到这一节。

同一版本号每次编译的 sha256 都不同，填的必须是放进官网的那一个。

合并 Release PR 前，确认 `web/public/downloads/` 里只有自己这次的改动：exe 在 diff 里只显示为二进制变更，线上玩家会自动更新到它。
