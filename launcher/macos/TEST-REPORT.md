# WindyMac 0.1.1 测试报告

测试日期：2026-10-17。环境：M4 Mac、macOS 26.6.2、Steam Mac Dota 2（Rosetta）；启动器与网络核心为 ARM64。地图 manifest：`8467070687660283526`。

## 已验证

- 离线协议回归、UDP 双向转发、中文名单、下一局与结束通知、上游 LocalGate/Relay 回归通过。
- 进图判定回归通过：断线时的 `Adding player SteamID` 不算成功；只有映射认证账号后的 `SIGNONSTATE_FULL` 才算进入，NONE 会撤销状态。旧版的进图成功判定不能作为稳定性证据。
- 后台临时应用可启动专用服并加载最新地图；清理测试确认不会删除符号链接指向的原游戏目录。
- 生产房间 API、同机运行的上游加入端核心直连/签名中转握手与名单传递通过。这不等同于 Windows 客户端实机测试。
- 游戏自带脚本启动单个前台客户端，主菜单就绪后自动发送连接；整个连接过程复用同一前台进程，后台专用服使用独立隐藏身份。
- 图形界面实测在 15:47:36 达到 FULL，15:48:27 进入选英雄；15:48:49 用户主动退出，连接持续约 73 秒。期间没有复现资源崩溃或 CPU 预算踢出，**90 秒连续观察未完成**。
- 服务器有限 CPU 处理预算的运行时回显已确认：burst 2000ms、rate 200ms。客户端命令行含 `fs_async_threads=16`，但没有隔离其作用，也未确认运行时有效值，不能把单次成功归因于它。
- 自带运行时应用的离线回归、退出生命周期回归及 ad hoc 签名检查通过。

## 故障证据与结论边界

已捕获 Dota 资源加载队列达到 32767 项后无法增长的引擎错误；仅等待主菜单的候选方案也曾复现。最终组合完成一次自动进图与选英雄，**不能证明已经根治该错误**。

另一次连接达到 FULL 后，服务器因处理消息耗时触发 `NETWORK_DISCONNECT_OVERFLOW`。有限预算设置后的上述短测未再次触发，长期效果待验证。没有修改资源引擎二进制或地图内容。

## 尚未验证

- 多次冷启动、长时间运行、完整游戏与结算、跨局恢复、满房负载。
- 另一台 Windows 电脑通过互联网加入并完成整局。已有真实远端加入到 FULL 的日志，但当时游戏已结束，不能作为跨平台可玩性通过证据。
- Mac 的游戏脚本启动与 SteamAPI 认证链路，在退出后切回游廊或其他模式时的行为；没有验证 VAC/反作弊兼容性，不能宣称反作弊安全已验证。
- Windows 原有 `test.cmd`、`build.cmd` 的本机执行；本报告所用环境为 macOS，Windows 发布链路未改动。
- Apple Developer ID 签名与公证；当前应用仅使用本地 ad hoc 签名。
