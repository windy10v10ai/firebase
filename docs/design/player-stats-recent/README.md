# 近期战绩（playerStatsRecent）

> 状态：已完成，对应 [#899](https://github.com/windy10v10ai/firebase/issues/899)。页面与接口见 [docs/web/README.md](../../web/README.md) 第 3 节「个人主页放什么」，配色与图标规则见 [docs/web/design-system.md](../../web/design-system.md)。

生涯战绩只有累计值，结算界面上的单局数据关掉就没了。本批给每个玩家留最近 50 场的单场明细，在个人主页展示。

## 决定

- **一个玩家一个文档，存定长 50 的数组**：个人主页读一次就够。没选一场一文档的子集合，主页要读 10 到 50 次；没选 Cloud SQL，成本翻倍且迁移还没做；没选 BigQuery 直接查，冷查询要 1–3 秒
- **刷分局跳过，口径与生涯战绩相同**：两份数据对不上，没法解释为什么这局在战绩里有、在累计里没有
- **不按 matchId 去重**：控制台启动的对局 matchId 恒为 `"0"`，防重复交给本地主机那条路已有的冷却窗口
- **出装与抽选技能先存后显示**：图标配齐之前数据已经在存，那段时间的对局不会永久缺这两项
- **出装照游戏结算界面画**：玩家在两边看到同一个样子
- **难度排在最左**：N8 的补刀、伤害整体比 N3 高，要先看到难度才读得懂后面的数

## 不做

- 不存全场十人的记分板：本地主机那条路每条请求只带一个玩家，凑不齐
- 不存技能品阶、行为分增减：当前展示用不上，后者还要改游戏端
- 不加历史清理：50 场封顶，文档大小恒定

## 后续事项

- 长期历史交给 BigQuery：第 51 场之前的数据现在会被截断。结算时同时写一份进 BigQuery，全服基线、按英雄胜率这类聚合算好再写回 Firestore
- 结算报文再加字段前，先用强制走代发的开关实测：代发把整条请求塞进 URL，加出装后约 1.6 KB，离常说的 2 KB 事件上限不远
- 物品 wiki 可以直接复用出装的图标与名字清单
