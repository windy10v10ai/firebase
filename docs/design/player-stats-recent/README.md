# 近期战绩（playerStatsRecent）

> 状态：已完成，对应 [#899](https://github.com/windy10v10ai/firebase/issues/899)；历史归档见文末「更久的战绩」。页面与接口见 [docs/web/README.md](../../web/README.md)「个人主页」，配色与图标规则见 [docs/web/design-system.md](../../web/design-system.md)。

生涯战绩只有累计值，结算界面上的单局数据关掉就没了。本批给每个玩家留最近 50 场的单场明细，在个人主页展示。

## 决定

- **一个玩家一个文档，存最近的单场明细**：个人主页读一次就够。没选一场一文档的子集合，主页要读 10 到 50 次；没选 Cloud SQL，成本翻倍且迁移还没做；没选 BigQuery 直接查，冷查询要 1–3 秒
- **刷分局跳过，口径与生涯战绩相同**：两份数据对不上，没法解释为什么这局在战绩里有、在累计里没有
- **不按 matchId 去重**：控制台启动的对局 matchId 恒为 `"0"`，防重复交给本地主机那条路已有的冷却窗口
- **出装与抽选技能先存后显示**：图标配齐之前数据已经在存，那段时间的对局不会永久缺这两项
- **出装照游戏结算界面画**：玩家在两边看到同一个样子
- **难度排在最左**：N8 的补刀、伤害整体比 N3 高，要先看到难度才读得懂后面的数

## 不做

- 不存全场十人的记分板：本地主机那条路每条请求只带一个玩家，凑不齐
- 不存技能品阶、行为分增减：当前展示用不上，后者还要改游戏端

## 更久的战绩

玩家想看到 50 场以前的战绩，所以主文档之外再存按页归档的历史，页面往下滚动自动加载。

- **主文档攒到 100 场，才把最老的 50 场整批搬成一页归档**：搬运摊到每 50 场一次，归档页写完不再改；每局多写一次的做法没选
- **归档页的 id 是 `玩家_页号`，页号越大越新，不用 matchId**：控制台开局的 matchId 恒为 `"0"`，当不了主键
- **一次请求只读一份文档，不足 50 场就顺势再补一页**：主文档里 50 场以后只剩几场时，前端不会拿到一小段就停住
- **不限期保留，不做清理**：一页约 50 KB，存储成本可以忽略
- **雷达图仍只看最近 50 场**：口径不随主文档涨到 100 场而变
- **搬运不用事务**：先写归档页再改主文档，中途失败时下一局重搬同一批并覆盖同号页；一个玩家同一时刻只在一局游戏里，不会有并发
- **没选**子集合加每场一文档（翻一页要读几十个文档）和 BigQuery 直查（冷查询要 1–3 秒）
- 上线前的第 51 场以后的战绩已经丢失，补不回来
