# 支付宝订单码支付

> 状态：已完成。回调地址见 [docs/api/README.md](../../api/README.md) 的「对外入口」，下单限额见同文「本地主机来源的限额」，金钱路径的幂等要求见同文「一致性」。价格表在 `api/src/alipay/alipay.constants.ts`。

国内玩家原本只有爱发电、Ko-fi 两条付款路子，都不方便。加上支付宝当面付的订单码：后端下单拿到二维码字符串，游戏与网站自己渲染，玩家扫码付款后由支付宝回调发放会员或积分。

## 决定

- **下单时由客户端带 steamId**：到账不靠爱发电、Ko-fi 那样的用户表反查，也不怕玩家留言填错
- **API 只回二维码字符串**：游戏端与网站各自渲染，服务端不出图
- **会员按月数阶梯折扣，积分包按份数线性计价，价格低于爱发电原价**：引导国内玩家走支付宝
- **回调按商户订单号幂等**：支付宝会重投，命中已成功的订单直接回成功，不重复发放

## 不做

- **回调丢失的兜底**：设计过「玩家输入支付宝交易号自助补单」和「定时扫描超时订单」，都没做，批次 6 也定了暂不考虑

## 后续事项

- 回调丢了就是玩家付钱不到账且没有告警。要补时两条路：玩家输入 25 位支付宝交易号，后端用 `alipay.trade.query` 反查本地订单再发放；或复用爱发电的定时对账，扫描超过 2 小时仍未付款的订单
