# 启动器反馈 阶段 1：启动器里报告问题、提出建议

> 状态：已完成，随启动器 0.4.2 发布，对应 #1311。接口见 [docs/api/README.md](../../api/README.md) 的 `POST /api/feedback`，分类与仓库标签见 [feedback-review](../../../.claude/skills/feedback-review/SKILL.md) 技能。

排查启动器问题一直卡在拿不到玩家日志。这一阶段让玩家在启动器里点一下，就把问题或建议连同日志发给我们。

## 决定

- **两种类型「报告问题 / 提出建议」，加最多 2 个一级「相关内容」**：玩家分不清需求和建议，两级分类也选不准；平衡算一种相关内容，可以和英雄、技能组合
- **报错原文、错误代码随报告附带，不给玩家看**：玩家看不懂
- **报告存 Firestore，日志压缩后存专用 GCS 桶，都是 90 天删**：没有外部依赖，网站与游戏共用同一接口；没选 GitHub issue，要维护 token、会被刷进仓库，也放不下日志
- **两份日志整份压缩上传**：专用服日志看地图脚本与 AI，客户端日志看连接与画面；客户端日志靠启动参数写成固定单文件，不用会越积越多的 `-condebug`
- **Steam ID 由启动器读注册表上报，不当可信身份**：不登录也能发，只用来对照战绩与日志
- **限频按 Steam ID 计，全站每天封顶**：国内代理转发的请求共用代理 IP，按 IP 计会让国内玩家互相挤占
- **隐私说明改成一句通用的话**：以后加功能只要在这个范围内就不用再改

## 不做

- 自动上传日志：只在玩家点发送时发
- 报告编号：玩家只管发
- 网页查看后台：先用 Firebase 控制台加 AI 汇总
