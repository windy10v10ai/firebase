# 启动器反馈 阶段 1：启动器里报告问题、提出建议

> 状态：设计中。对应 issue #1311；网站的反馈见 #1379，沿用本文的分类与接口。

排查启动器问题（断线、反作弊提示、AI 发呆）一直卡在拿不到玩家日志。这一阶段让玩家在启动器里点一下就把问题或建议连同日志发给我们，不用找文件、不用加群报编号。我定期看报告，或者让 AI 汇总。

## 玩家看到什么

- **两个入口**：主窗口右下角「开发选项」左边常驻一个「反馈」；出错时报错条上的「打开日志」换成「反馈问题」，点开后自动选好「报告问题」+「启动器」。报错原文在后台随报告发出，不在弹窗里显示
- **一个盖在启动器上方的小窗口**：右上角 ✕ 和「取消」只关闭反馈，不影响启动器和进行中的游戏。选类型、选「相关内容」、写描述，点发送。必填项在标题后加红色星号，不写「（必填）」「（选填）」。成功后弹窗关闭，主窗口显示「已收到你的反馈，谢谢！」；失败时留在弹窗提示重试，已填的内容保留
- **不给报告编号**：玩家只管发，后续由我们看
- 画面设计见 [Artifact](https://claude.ai/artifact/J2BirHoWHPRYQYSpCowzGZ)

## 分类

启动器与网站共用这一套，后台按它统计与汇总。

**类型**（必选，二选一）：

| 中文 | 英文 | 俄文 | 日志 | 描述 |
|---|---|---|---|---|
| 报告问题 | Report a problem | Сообщить о проблеме | 默认勾选 | 选填 |
| 提出建议 | Suggest an idea | Предложить идею | 默认不勾 | 必填 |

**相关内容**（英文 Related to，俄文 Касается；界面只提示「最多 2 个」，不写可不选，免得玩家都跳过；一个都不选即「其他」）。对应标签是 AI 汇总时转成 issue 用的：

| 玩家看到的 | 对应仓库标签 |
|---|---|
| 英雄 | game `hero` |
| 技能 | game `ability` `4+3` |
| 觉醒 | game `awaken` |
| 物品 | game `item` |
| 电脑 AI | game `bot` |
| 平衡 | game `balance` |
| 界面 | game `UI/UX` |
| 会员 | game `member` |
| 卡顿 / 掉线 | game `system` |
| 启动器 | firebase `launcher` |
| 网站 | firebase `web` |

另留一个 `tags` 数组，玩家提交时为空，AI 汇总时补更细的标签。

## 决定

- **玩家只选一级「相关内容」，最多 2 个**：两级玩家选不准，细类要看日志才能定；多选会全勾，2 个够表达「英雄 + 平衡」这类组合
- **需求和建议合并成「提出建议」，平衡放进「相关内容」**：玩家分不清需求与建议；平衡本质也是建议，放在这里可以与英雄、技能组合
- **两种类型都能附带日志，提出建议默认不勾**：建议偶尔也需要看当局情况；勾选框旁的说明写「能帮我们更快找到并解决问题」
- **报错原文、错误代码不给玩家看**：玩家看不懂，后台随报告附带即可
- **报告存 Firestore，日志压缩后存 GCS，90 天后删除**：网站以后共用同一个接口，加「来源」字段即可；没有外部依赖，数据留在自己的 GCP。没选 GitHub issue，因为要维护 token、会被刷进仓库，而且 issue 放不下日志
- **日志整份压缩上传，不截尾**：客户端日志一局 1～3MB、最大见过 40MB，压缩后约 45KB～370KB
- **两份日志**：专用服日志看地图脚本与 AI，客户端日志看连接与画面。加入联机的玩家只有客户端日志
- **客户端日志靠启动时加 `-con_logfile client.log`，固定单文件每次覆盖**：没选 `-condebug`，它会把旧文件改名存档、越积越多
- **Steam ID 由启动器读注册表上报，不登录也能发**：只用来对照战绩与日志，不当可信身份；读不到就不带。网站登录后的 Steam ID 可信，记录里标明来源
- **限频按 Steam ID 计，全站也封顶**：每人每小时 3 次、每天 10 次，没有 Steam ID 才按 IP；全站每天 500 次。国内代理转发的请求共用代理 IP，按 IP 计会让国内玩家互相挤占
- **大小**：每份日志只取最后 20MB 原文，压缩后不超过 1MB；描述 1000 字，按英文、俄文的长度定，中文玩家碰不到
- **只收启动器自己的两份日志**：玩家不能选文件，接口只认 gzip
- **报错原文、出错步骤与异常信息存进报告的 `launcherError`**：不给玩家看，看报告时直接可读
- **日志存专用的 GCS 桶，不开 Firebase Storage**：只有函数读写，不需要客户端直连的安全规则
- **隐私说明改成一句通用的话**：「单人游戏时不会共享你的信息；联机、反馈等需要时，本站才会获取你的 Dota2 ID、网络地址、游戏日志等必要信息，只用于联机和改进游戏，最多保留 90 天后删除。」以后加功能只要在这个范围内就不再改

## 不做

- 不自动上传日志：只在玩家点发送时发
- 不给玩家报告编号
- 不做网页查看后台：先用 Firebase 控制台加 AI 汇总，需要时再做
