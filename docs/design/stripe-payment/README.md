# Stripe 月会员付款

> 状态：后端进行中（#1563），网站入口 #1564、上线配置 #1565 未开始。回调地址与凭据见 [docs/api/README.md](../../api/README.md) 的「对外入口」「对外依赖」，回调的幂等做法见同文「一致性」。

海外玩家只能走 Ko-fi，付款时要在留言里手填游戏 ID，填错就不到账。网站加一条 Stripe 付款：玩家登录后买一个月高级会员，付完自动到账。

## 决定

- **只卖一个月高级会员，一次性付款，按现有 US$4 标价**：首期先把链路跑通，多月、积分包、自动续费以后再加
- **订单记商品代码与份数，发放内容查商品表**：与支付宝订单同一种写法，以后加积分包、多月会员只改商品表和下单入参，订单结构不变
- **订单归属只认网站登录身份**：下单接口不收 steamId，不再有手填 ID 填错的问题；与支付宝不同，不支持替别人下单
- **用 Stripe 托管收银台，只开银行卡与钱包（Apple Pay、Google Pay、Link）**：这些方式付款当场就有结果，回调只需处理一种成功事件；支付宝、微信在 Stripe 上申请未通过
- **回调照搬支付宝的顺序**：订单已成功直接回成功，否则验签、校验金额币种后发放，最后改订单状态；不加「发放中」状态，不上事务，发放失败让 Stripe 重试
- **不做主动查单补发**：Stripe 回调失败会重试数天并发邮件提醒，后台也能手动重发，补发的价值抵不上它带来的并发问题
- **付款结果页轮询订单状态**：与支付宝弹窗一致，查到成功才显示已到账；查询接口只返回本人的订单
- **退款与拒付人工处理**：在 Stripe 后台操作，需要时手动扣回会员，不接这两类回调

## 不做

- 自动续费、多月购买、积分包、优惠码：首期范围外
- 游戏内入口：另行规划
- 处理收银台过期：未付款的订单停在待付款，没有副作用
- 下单次数限额：建收银台不花钱，且必须登录才能下单

## 后续事项

- 上线前在 Stripe 后台登记正式回调地址，把 `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET` 存进 Secret Manager（#1565）。函数部署会挂载这两个 secret，缺了会部署失败
- Stripe 账号以日元结算，美元收款会产生换汇费
