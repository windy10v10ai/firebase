# Stripe 会员与积分付款

> 状态：后端（#1563）、网站入口（#1564）已完成，多月会员与积分（#1577）进行中，上线配置 #1565 未开始。回调地址与凭据见 [docs/api/README.md](../../api/README.md) 的「对外入口」「对外依赖」，回调的幂等做法见同文「一致性」。

海外玩家只能走 Ko-fi，付款时要在留言里手填游戏 ID，填错就不到账。网站加一条 Stripe 付款：玩家登录后买高级会员或会员积分，付完自动到账。

## 决定

- **会员卖 1、3、12、36 个月，积分卖三档，都是一次性付款**：档位与支付宝一致，1 个月保持 Ko-fi 的 US$4；自动续费以后再加
- **美元价按支付宝的人民币价折算（US$4 对 ¥28），总价取 .99 结尾**：与支付宝同价，又是海外常见的标价；多月会员按档写死总价，不按月价相乘
- **折扣对比 Ko-fi 原价**：Ko-fi 是海外玩家原来的付款方式，按支付宝的比例标反而看不出比 Ko-fi 便宜多少
- **订单记商品代码与份数，发放内容查商品表**：与支付宝订单同一种写法，加档位只改商品表
- **订单归属只认网站登录身份**：下单接口不收 steamId，不再有手填 ID 填错的问题；与支付宝不同，不支持替别人下单
- **用 Stripe 托管收银台，只开银行卡与钱包（Apple Pay、Google Pay、Link）**：这些方式付款当场就有结果，回调只需处理一种成功事件；支付宝、微信在 Stripe 上申请未通过
- **回调照搬支付宝的顺序**：订单已成功直接回成功，否则验签、校验金额币种后发放，最后改订单状态；不加「发放中」状态，不上事务，发放失败让 Stripe 重试
- **不做主动查单补发**：Stripe 回调失败会重试数天并发邮件提醒，后台也能手动重发，补发的价值抵不上它带来的并发问题
- **付款结果页轮询订单状态**：与支付宝弹窗一致，查到成功才显示已到账；查询接口只返回本人的订单
- **退款与拒付人工处理**：在 Stripe 后台操作，需要时手动扣回会员，不接这两类回调
- **网站入口是付款方式里的第三个标签「Stripe」，英文、俄文默认选它**：海外玩家最该用这一家；档位排法与支付宝相同
- **商品名、权益、商品图与收银台外观每单由代码传，不在 Stripe 后台建商品**：文案跟着网站语言走，测试与正式账号不用各配一遍；收银台语言同样跟随网站
- **权益列表用全角空格撑出换行**：收银台会把普通换行合并成空格，长串全角空格比任意一行都宽，实测三种语言、电脑与手机宽度都能逐条换行
- **收银台按钮上方写明这单发给哪个 Dota2 ID**：玩家付款前能确认账号
- **跳回后的结果弹窗等太久就停止查单**，显示「还在确认中」并可手动刷新：付款成功的订单回调迟早会到，不让页面无限转圈

## 不做

- 自动续费、优惠码：范围外
- 游戏内入口：网站上线稳定后再做（windy10v10ai/game#2601）
- 处理收银台过期：未付款的订单停在待付款，没有副作用
- 下单次数限额：建收银台不花钱，且必须登录才能下单

## 后续事项

- 上线前在 Stripe 后台登记正式回调地址，把 `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET` 存进 Secret Manager（#1565）。函数部署会挂载这两个 secret，缺了会部署失败
- Stripe 账号以日元结算，美元收款会产生换汇费
