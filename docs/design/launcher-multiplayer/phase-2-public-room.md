# 启动器联机 阶段 2：公开房间

> 状态：设计已定，未实现。阶段 1 的房间、隧道与 API 见 [phase-1-friend-room.md](phase-1-friend-room.md)。

阶段 1 只能凭房间码加入，开房的人得自己找朋友。这一阶段让房间默认公开，玩家在「加入联机」页从列表里点一下就进；凭房间码加入留给私密房间。界面设计稿见 [启动器房间列表](https://claude.ai/artifact/HvseKHysxmNLcLQhqbkbg4)。

## 玩家流程

**加入联机**

- 页面以公开房间列表为主，下方保留「私密房间：输入房主发来的房间码」，没填满 6 位时「加入」是灰的
- 每行显示房主头像与昵称、地图（简单 / 困难 / 自定义）、人数（如 4/10）、延迟档位、「加入」按钮
- **延迟是实测的**：列表一出来就对每个房间试打一次洞，结果用三格信号图标表示：低于 60 ms 三格绿、60–120 ms 两格黄、高于 120 ms 一格红；测试中显示转圈，打不通显示带斜线的灰色信号。鼠标停在图标上显示毫秒数。数字每次刷新都会跳，档位一眼就能看懂
- **能进才能点**：测试中、打不通、满员的房间按钮是灰的，打不通和满员整行置灰
- **排序**：能进的在前，人多的在前，人数相同按延迟；测试中的居中，打不通和满员的垫底。打不通的不隐藏，否则对称型网络的玩家只会看到空列表
- 所有房间都打不通时，列表上方提示网络暂时无法加入公开房间，后续版本解决
- 列表不显示开房时间，靠下面的「15 分钟暂停」把挂机的房间拿掉

**联机主机**

- 难度按钮上方一行设置：「房间类型：公开 / 私密」与「人数上限」下拉（2–10 人，默认公开、10 人）。开房后两项都能改，2 秒内生效；上限不能低于房里已有人数
- 私密房间不进列表，只能凭房间码加入
- 玩家列表里每个加入者右侧有 ×，点了先变成「移出 xx？[移出] [取消]」，3 秒不点自动取消
- 被移出的人看到「你已被房主移出，不能再加入这个房间」，这个房间也不再出现在他的列表里。只限这一个房间，房主重开房就清空，不做跨房间的黑名单

**记住上次的选择**：启动器打开时回到上次的分段（单人游戏 / 联机主机 / 加入联机），房间类型与人数上限也沿用上次的值。只恢复界面，不自动开房。

**头像缓存**：Steam 头像下载过就存到本地，下次直接用。Steam 换头像后地址会变，按地址存就不会显示旧头像；30 天没用过的文件删掉。

**对称型网络的提示**：建房或加入时，启动器查到自己是对称型网络就提示「你的网络类型可能无法联机，将在后续版本解决」。

## 测试连通

流程与加入相同，只是打通后不进游戏：

- 加入者把自己的候选地址交给 API，指名要测的房间，拿回房主的候选地址与一次性测试令牌；房主下次轮询拿到同一份，两边开始握手
- 房主的隧道认得测试令牌，回应握手但不加进玩家列表、不开端口连专用服；加入者用握手往返时间当延迟
- 加入者所有测试共用一个 UDP 端口，同时测所有房间。打通的路保留着，点「加入」时直接用，几乎不用等
- 每个房间同一次打开加入页只测一回，刷新时只测新出现的房间

公开房间本来就让任何人都能拿到房主 IP，所以测试连通时交换 IP 可以接受。

## 降低服务器压力

| 谁 | 频率 | 理由 |
|---|---|---|
| 房主轮询 | 开房后 5 分钟内每 2 秒，之后每 5 秒 | 多数人开房后几分钟内加入，这段要快；打洞窗口 15 秒，5 秒的间隔只让加入多等一两秒。挂满 15 分钟的房间请求从 450 次降到 270 次 |
| 房主轮询 | 开房 15 分钟还没开局就停止 | 挂机的房间不再一直请求 |
| 加入页列表 | 每 30 秒自动刷新，右上角一直有「刷新」按钮 | 窗口最小化、不在最前，或停在加入页超过 5 分钟就停止自动刷新，按钮仍可用 |

**15 分钟暂停**：停止轮询后房间在 2 分钟内失效，列表里没有了，凭码也进不来，公开、私密一样。房主那边出现提示条「房间已暂停：开了 15 分钟还没开局」和「继续等人」按钮，点了恢复轮询，房间码不变，再算 15 分钟。人不在电脑前就不会点，房间自然消失。

**列表缓存**：API 在内存里缓存整份候选房间 3 秒，所有人共用，按各自条件在内存里过滤。不管多少人在看，每个服务器实例每 3 秒最多查一次 Firestore。Cloud Functions 第二代跑在 Cloud Run 上，实例处理完请求不会立刻销毁，模块级变量会保留；实例回收或多开时只是多查一次。缓存只按「2 分钟内有心跳」一个条件查，其余条件在内存里过滤，所以不用建组合索引。

## API

在阶段 1 的两个接口上扩展，再加一个：

- **房主轮询多报几样**：公开与否、人数上限、地图（简单 / 困难 / 自定义）、当前人数、被移出的 Steam ID。房主点「继续等人」时，即使房间已过了 2 分钟的有效期，带对房主令牌的轮询也能让它恢复，房间码一天内不会被别人占用
- **房间列表**（新）：返回公开、未开局、2 分钟内有心跳、地图版本与隧道协议版本都与请求者相同、请求者没被这个房间移出的房间
- **测试连通**：加入接口带一个测试标记，校验与加入相同、不查昵称头像、不受满员限制，房主轮询拿到的记录也带这个标记，见上一节；测试请求和加入请求一样设 TTL
- **加入多两种拒绝**：满员返回「房间已满」，被移出过返回「你已被移出」

**不兼容旧版本**：隧道协议版本加 1（新增测试与移出两种包），新旧版之间的加入由现有的协议版本比对拦下并提示双方更新。旧版房主不报公开标记，按私密处理，不进列表。只是小范围测试，不为旧版写额外代码。

## 不做

- **房间名**：玩家自填的文字要审核，不值得
- **按地区估延迟**：同一国家内南北差别也大，不如实测
- **跨房间的黑名单**：要在 API 长期存名单，等有需求再做
- **列表显示房内所有玩家的头像**：房主每次轮询都要报完整名单，列表数据多好几倍
- **兼容 0.3.x**：理由见「API」
