# 启动器联机 阶段 1：好友开房

> 状态：已实现，公测中。启动器侧的长期约定见 [launcher/README.md](../../../launcher/README.md) 的「联机」。

用启动器开局目前只能单人。这一阶段让房主用启动器开房，朋友凭房间码加入同一局，不要求任何人有公网 IP，也不用设置路由器。

## 已验证

用一次性测试版启动器在两台电脑上验证过：

- **玩家自建专用服能联机**：另一台电脑按 IP 连入，Steam 验证、选英雄、游戏内互动、结算都正常，结算记录了两个人。游戏与 API 不用改
- **走不了 Valve 的网络**：专用服开了 `net_p2p_listen_dedicated` 也不接受 Steam P2P 连接，中转名额为 0，Valve 的打洞与中转都用不上。所以跨网连接由启动器自己做

## 玩家流程

- 顶部分段切换「单人游戏 | 联机主机 | 加入联机」，默认单人。单人和现在完全一样：不调 API、45 秒自动开始。分段比勾选框更显眼，三种开局方式也更对等
- **房主**在「联机主机」点难度：专用服启动，启动过程分步显示；房间码一拿到就显示在「复制」按钮左侧，不等专用服就绪。房主的 Dota 照常自动进游戏，等人到齐后手动开始
- **朋友**在「加入联机」填房间码点「加入」：几秒内连通就自动启动 Dota 进入房主的游戏；连不上提示「换一个人当房主，或从游廊开局」
- **玩家列表**：房间码下方两列显示每个人的头像、昵称、状态，房主与自己带标记，一眼看到 4–5 人、最多 10 人可滚动。两边状态统一为连接中 / 已连通，正在载入 / 已进入游戏 / 连接失败 / 已离开，按 Steam ID 去重，重进不留旧行。加入者看到的列表由房主经隧道转发，不另调 API
- **地图必须最新**：切到联机分段时，地图不是最新就用提示卡代替开局按钮，卡上只有「打开创意工坊」。提示放在切换时而不是点击后，玩家不会白等
- **关闭时通知对方**：房主关服务器，加入者立刻显示房主已关闭；加入者离开，房主列表里变成已离开

## 整体结构

```
房主电脑                                       朋友电脑
专用服（只听 127.0.0.1）                        Dota 客户端（连 127.0.0.1）
      ↕ 本机                                          ↕ 本机
启动器隧道  ◄──────── 游戏数据（UDP）────────►  启动器隧道
      │                                               │
      └── HTTP：开房、轮询、关房 ──► API + Firestore ◄── HTTP：凭房间码加入
          两边各自向公共 STUN 查自己的公网地址
```

- **Dota 两边都只连本机**：跨网的只有两个启动器之间的隧道，验证过的 Dota 行为原样沿用，不改 Dota 文件
- **API 只牵线**：开房、查房、交换双方地址。连通后游戏数据不经过我们的服务器，没有流量费
- **公网地址用公共 STUN 查**：Cloud Functions 收不了 UDP；启动器内置国内外多个公共 STUN，轮流试
- **三条路同时试，按局域网 > UPnP 直连 > 打洞取用**：局域网回包最快，自然先通；同时试省掉逐条失败的等待。同一局域网走打洞要靠路由器回环，很多路由器不支持，所以局域网优先
- **UPnP**：启动器请求房主路由器把外部端口转给隧道，只在路由器本身有公网 IP 时有用，作为打洞之外的一条路

## 房间

- **存 Firestore**，一个房间一条文档，文档 ID 就是房间码
- **房间码**：6 位，字符集去掉 `0 O 1 I L` 等易混字符，共 31 个
- **去重**：生成后先查，码被一天内开的房间占着就换一个，不覆盖别人的房间
- **只在开局前接受加入**：房主启动器从专用服日志读到进入选英雄阶段时，最后一次轮询带上开局标记；之后再加入返回「游戏已开始」。掉线重连不经过 API，见「隧道」
- **有效期靠轮询**：房主的轮询同时充当心跳，超过 2 分钟没收到视为关闭。房主关服务器、启动器崩溃、开新房都靠这条让旧房间失效，不另设关房请求。查房时 API 自己判断过期，不依赖 Firestore TTL 何时真正删掉文档（TTL 可能延迟 24 小时）
- **房间码是唯一凭证**：知道码就能加入。专用服仍校验每个人的 Steam 账号，冒充不了别人

## 统计

连接结果写 BigQuery 新表 `launcher_room_events`，一行一个事件，和房间文档互不依赖：文档删了统计照样在。事件用开房时生成的随机 `room_id` 关联房主与加入者，不用房间码，因为码过期后会被复用。

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_time` | TIMESTAMP | 分区键（按天） |
| `event` | STRING | `room_created` / `join_succeeded` / `join_failed`，聚类键 |
| `room_id` | STRING | 开房时生成 |
| `path` | STRING | 连通所走的路：`lan` / `upnp` / `punch`；失败为空 |
| `elapsed_ms` | INT64 | 房主拿到加入请求到连通或放弃 |
| `host_upnp` | BOOL | 房主路由器是否成功开了端口 |
| `host_public_ip` | BOOL | 房主 STUN 查到的地址是否等于 UPnP 外部地址，即路由器有公网 IP |
| `host_symmetric_nat` | BOOL | 房主是否为对称型 NAT：同一端口问两台 STUN，看到的外部端口不同。打洞基本必败，用来解释失败原因；只拿到一个结果时为空 |
| `joiner_upnp` | BOOL | 加入者路由器是否成功开了端口 |
| `joiner_symmetric_nat` | BOOL | 加入者是否为对称型 NAT |
| `launcher_version` | STRING | |
| `country` | STRING | 按请求来源判定 |
| `steam_id` | INT64 | 上报者：开房是房主，加入是加入者。启动器从注册表 `HKCU\Software\Valve\Steam\ActiveProcess` 的 `ActiveUser` 读，可伪造，只用于排查 |
| `host_steam_id` | INT64 | 房主，API 从房间文档取 |

`room_created` 由开房请求写入；加入结果由房主在下一次轮询里上报，加入者的 Steam ID 与网络情况取自加入时存下的文档，所以加入者不用再调接口。房主在连接过程中崩溃时这次结果会丢，不影响看失败率。

不记 IP 地址。写入沿用现有 best-effort 方式，失败不影响开房和加入。建表 SQL 放仓库根目录 `bigquery/`。

## 隧道

- **每个启动器只开一个 UDP 端口**：查 STUN、打洞、传数据共用，STUN 查到的地址才是后面真正用的地址
- **加入时序**：加入者把自己的候选地址（局域网、STUN、UPnP）连同房间码交给 API，立刻拿回房主的候选地址与一次性加入令牌，不等房主响应；房主下一次轮询拿到同一份。两边每 0.2 秒向对方所有候选地址发带令牌的握手包，最多 15 秒，窗口要远大于轮询间隔；第一条路通后再等 0.3 秒看局域网是否也通，按优先级定路
- **房主每 2 秒轮询一次**：API 无法主动通知家里内网的启动器，只能由它来问；打洞要求两边几乎同时发包，间隔决定了加入者最多等多久。只在开局前轮询，一局约 150 次请求
- **多个朋友**：房主按对方公网地址区分，每个朋友在本机单独开一个端口连专用服，专用服看到的是几个独立客户端
- **数据包**：1 字节类型（握手 / 数据 / 保活）加 Dota 原始数据，只有握手带令牌；不认识的地址发来的包丢弃
- **保活**：10 秒无数据发保活
- **关闭通知**：任一方关闭时发几次「再见」包，对方不用等超时
- **玩家列表**：房主每 2 秒把列表随保活发给每个加入者
- **隧道断开自动重连**：30 秒收不到对方任何包，加入者用原令牌重新握手，房主仍认这个令牌，不经过 API。Dota 自己约 30 秒才判定掉线，重连够快时玩家只会卡一下
- **Dota 关闭后重进**：加入者的 Dota 关掉后启动器保持隧道，显示「重新进入游戏」，点击重开 Dota 连本机隧道，直到房主那边结束。已实测同一账号重进回到原位置、原英雄
- **已实测**：局域网约 0.2 秒连通；一方连手机热点、一方用家庭宽带，两边路由器都没开端口，打洞约 0.6 秒连通；Windows 防火墙没有弹窗，两边都先向对方发包，回来的包被当作回应放行。UPnP 路线还没遇到支持它的路由器，没测到

## API

两个公开接口，挂在 `/api/launcher/` 下，沿用启动器接口的约定（exe 里的密钥等于公开，所以不用密钥）。权限靠 API 发的随机令牌：只有房主能看到谁要加入、能关房；知道房间码的人只能发起加入，看不到其他加入者。

| 接口 | 调用方 | 次数 | 做什么 |
|---|---|---|---|
| `POST /launcher/rooms/host` | 房主 | 开房 1 次，开局前每 2 秒 1 次 | 不带房间码是开房，返回房间码与房主令牌；带码与令牌是轮询，返回最近 30 秒的加入请求（含加入者的 Steam ID、昵称、头像），并上报已完成的加入结果；带开局标记后不再接受加入 |
| `POST /launcher/rooms/:code/join` | 加入者 | 每人 1 次 | 提交自己的候选地址与地图版本，返回房主候选地址、加入令牌、房主与自己的昵称头像；房间不存在、过期返回 404，已开局、协议版本或地图版本不同返回 409 |

- **Firestore**：房间与加入请求各一个集合，加入请求按房间码查。都设 TTL，保留 7 天：候选地址里有 IP，不长期保留；留几天是为了能查最近开的房间
- **昵称头像由 API 顺带返回**：启动器只有自报的 Steam ID，查 Steam 资料要密钥，只能放在服务端；查不到时不影响开房和加入
- **地图版本由 API 比对**：双方各自上报本机地图的创意工坊版本号，任一方没报就不比，比对结果决定提示谁去更新
- **IP 可见范围**：打洞要求双方互知 IP，拿到房间码的人能看到房主的 IP，反之亦然。所有点对点联机都这样，第一版接受
- **不做限流**：码约 9 亿种、同时开着的房间几十个，猜中概率极低；Cloud Functions 拿不到可信 IP，Steam ID 又是自报的，限不住。只做输入校验：候选地址最多 8 个且格式为「类型:IP:端口」。日志里真出现滥用再加

## 游戏侧：联机主机的开局

现状（game 仓库）：设置阶段 45 秒自动开始；全员投完难度 3 秒后定稿，定稿后倒计时缩到 10 秒。保存了难度预设的玩家进来就自动投票，只有房主一人时会马上定稿并开始，朋友来不及进。

- **启动器开房时带 `+hostname` 设一个固定的服务器名**，游戏在专用服上读 `hostname` 识别联机主机。自动性能测试已在用同样的方式识别专用服
- **联机主机时**：服务端关掉自动开始；设置界面里「难度定稿后倒计时缩到 10 秒」只在自动开始开着时执行，所以预设投票与全员投完都不触发倒计时。由房主用 Dota 默认的「锁定并开始」按钮开始；没有房主权限的人本来就看不到这个按钮，不改
- **其他模式不变**：单人用启动器开局、从游廊开局（单人或多人）照旧

## 错误提示

| 谁 | 情况 | 提示 |
|---|---|---|
| 房主 | 开房时连不上 API | 开房失败，请检查网络后重试；单人开局不受影响 |
| 房主 | 公共 STUN 全部失败 | 不提示，照常开房，少一条打洞的路，计入统计 |
| 房主 | 首次开房 | 提示条预告 Windows 可能询问是否允许联网 |
| 加入者 | 房间码不存在或过期 | 房间不存在或已关闭，请核对房间码 |
| 加入者 | 已进入选英雄 | 游戏已开始，无法加入 |
| 加入者 | 15 秒未连通 | 连接失败，换一个人当房主，或从游廊开局 |
| 加入者 | 双方地图版本不同 | 自己的地图是最新版：提示房主更新地图；否则提示自己先更新。双方地图版本不一致进游戏可能出错 |
| 加入者 | 双方隧道协议版本不同 | 请双方都更新启动器；开房时记下协议版本，加入时由 API 比对 |

## 测试与上线

- **API**：单元测试覆盖房间码去重、过期、令牌校验、开局后拒绝加入，再用本地 emulator 跑通开房到关房
- **game**：联机主机一直等房主开始；单人用启动器开局、从游廊开局的倒计时不变
- **启动器**：同一局域网两台电脑测局域网路线、多个朋友、两种重连；开手机热点测跨网打洞；在没装过启动器的电脑上看防火墙是否弹窗

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | 本设计文档 | 先合 |
| 2 | API | 两个接口、Firestore、BigQuery 建表 SQL，`docs/api/README.md` 补接口约定 |
| 3 | game | 联机主机关自动开始，随 5.61b 发布，不写更新日志。必须先于启动器上线，否则开房后游戏仍会自动开始 |
| 4 | 启动器 | 开局分段、房间码、玩家列表、隧道、UPnP、STUN、重连，`launcher/README.md` 补联机架构。公测用的 exe 以 0.3.5 私下发给玩家，不上官网 |

## 不做

- **中转服务器**：先看统计里的失败率再决定
- **账号与权限**：第一版房间码就是凭证，专用服仍校验 Steam 账号
- **限流**：理由见「API」，生产日志里出现滥用再加
- **列表里显示 Dota 内的掉线**：加入者自己的启动器已有「重新进入游戏」，房主在游戏里也能看到谁断开
- **房主有公网 IP 时让专用服对外开放、网页给 `connect` 直连链接**：只覆盖一部分房主，不如做服务器主机

## 后续阶段

- **中转服务器**：看统计里的失败率再决定；可与服务器主机放在同一台机器上
- **服务器主机（自建）**：玩家可选 windy 提供的服务器或玩家自己开的房，细节到时再定
- **公开房间列表**：房间已存在 API 里，加公开标记与列表接口即可
- **网页显示房间、网页唤起启动器加入**：浏览器发不了打洞用的 UDP，加入方仍需启动器。启动器注册 `windy10v10ai://join/房间码` 这类链接，网页点击唤起；注册链接也算对电脑的改动，要同步代码签名政策页
- **开局后迟到加入**：第一阶段选英雄后关房，迟到的人这一局进不来
