# 启动器联机 阶段 1：好友开房

> 状态：已完成，随启动器 0.4.0 发布。启动器侧的长期约定见 [launcher/README.md](../../../launcher/README.md) 的「联机」，API 与统计表见 [docs/api/README.md](../../api/README.md) 的「启动器联机」。

用启动器开局原来只能单人。这一阶段让房主开房，朋友凭房间码加入同一局，不要求公网 IP，也不用设置路由器。

## 决定

- **两边 Dota 都只连本机，跨网的只有两个启动器之间的 UDP 隧道**：单人模式验证过的 Dota 行为不变，也不改 Dota 文件
- **自己做隧道，不走 Valve 的网络**：实测专用服不接受 Steam P2P 连接，Valve 的打洞与中转都用不上
- **API 只牵线，游戏数据不经过我们的服务器**：没有流量费；公网地址用公共 STUN 查，Cloud Functions 收不了 UDP
- **局域网与打洞同时试，局域网优先**：同时试省掉逐条失败的等待；同一局域网打洞要靠路由器回环，很多路由器不支持
- **不用 UPnP**：公测首日开了 UPnP 的玩家拿到的都是内网地址，一次都没用上，还被怀疑引起 Defender 误报
- **房主每 2 秒轮询**：API 无法主动通知家里内网的启动器，打洞又要两边几乎同时发包
- **房间码就是凭证，不做限流**：理由见 docs/api/README.md
- **联机主机关掉游戏的自动开局，由房主手动开始**：只有房主一人时预设难度会马上定稿开局，朋友来不及进

## 不做

- 中转服务器：先看失败率，后来见[阶段 4](phase-4-relay.md)
- 列表里显示 Dota 内的掉线：加入者自己的启动器已有「重新进入游戏」
- 房主有公网 IP 时让专用服对外开放：只覆盖一部分房主

## 后续事项

- 网页唤起启动器加入：浏览器发不了打洞用的 UDP，要启动器注册链接协议，注册也算对电脑的改动，要同步代码签名政策页
- 开局后迟到加入
