# 启动器联机 阶段 4：中转服务器

> 状态：设计已定，API 发通行证随本设计一起实现；中转程序在 server 仓库，启动器另开 PR，随 0.5.0 发布。长期说明见 [启动器联机](../../../launcher/README.md#联机)。

对称型网络打洞必败，公测首日约三分之一的加入者是这种网络，只能看到「连接失败」。这一阶段加一台中转服务器，打不通的玩家改走中转。

## 系统构成

```
            ┌──────────── API（Cloud Functions）────────────┐
            │  开房 / 轮询 / 加入                           │
            │  私钥（Secret Manager）给每次加入签通行证     │
            │  响应里附：通行证 + 中转地址                  │
            └───────▲─────────────────────────────▲─────────┘
                    │ HTTP                         │ HTTP
 房主电脑           │                              │         加入者电脑
 专用服 ⇄ 启动器 ───┘                              └─── 启动器 ⇄ Dota
            │  ① 局域网 / ② 打洞：直接相连            │
            │◄────────────────────────────────────────►│
            │  ③ 中转（腾讯云上海，国内 BGP 多线）     │
            └────────►  中转服务器  ◄──────────────────┘
                       公钥在配置文件里：验签、分配端口、双向转发
```

## 决定

- **中转是第三条路，和局域网、打洞同时试**：局域网 > 打洞 > 中转；中转先通也等到握手开始后 3 秒，没有更好的路才用它。能打洞的玩家照旧约 1 秒连通，对称型网络约 3 秒；先打洞失败再试中转要白等 15 秒。
- **选路仍由加入者决定再告诉房主**：沿用现有握手，不用另设两边商量的机制。
- **每次加入在中转上分一个单独的端口**：房主按对方地址区分朋友，每对一个端口，房主看到的只是「这个朋友的地址是中转的某个端口」，隧道代码不用改。
- **在分到的端口上认领一次才开始转发**：对称型网络换目标端口就换对外地址，必须在那个端口上认准对方。空闲 2 分钟回收端口。
- **API 用私钥签通行证，中转只拿公钥验**：中转不连 API、不连数据库，只验签名和有效期；公钥可公开，直接写在 server 仓库的配置里，部署不用传秘密。私钥放 Secret Manager，与现有密钥一样。
- **通行证有效 6 小时**：游戏中途掉线重连要拿同一张通行证重新认领，有效期要盖住一整局。发出后收不回：被移出的人仍能在中转登记，但房主已不认他的令牌，转来的包会被丢掉。
- **中转地址由 API 下发，不写死在启动器里**：换机器、加节点只改 API；API 不配地址时不发通行证，所有人照旧只走局域网和打洞，这也是关掉中转的开关。
- **只放国内一台**：海外家用网络多数能打洞；海外玩家打不通时绕到国内延迟高，总比连不上强。看统计里走中转的占比与地区再定加不加海外节点。
- **中转程序自己写，不用 TURN**：只需要「配对、转发」，启动器是老版本 C#，接 TURN 客户端比实现一个小协议麻烦。放 server 仓库，Node 实现。
- **上线后先用按量计费的云服务器跑几天，按实测流量再买年付**：每名玩家的实际流量没测过，3Mbps 这类小带宽套餐可能不够；按量计费按小时扣费、带宽上限可调，几天几十元。中转程序按局记录流量、10 秒峰值与同时在用的对数，作为选套餐的依据。用普通按量计费，不用竞价实例，后者可能被回收。
- **`--relay-only` 启动参数**：加入者只向中转发握手，用来在能打洞的电脑上实测中转；只有加入者需要带，房主不用。
- **隧道协议版本加 1**：旧版房主不认识中转这条路，新旧混用时由现有的版本比对提示双方更新。

## 接口约定

API 与中转跨两个仓库，按这里实现。

- **通行证**：`base64url(载荷) + "." + base64url(签名)`，载荷是 JSON `{"j":"<joinId>","r":"h"|"j","e":<过期 Unix 秒>}`，`r` 区分房主与加入者，签名用 Ed25519。同一个 `joinId` 的房主与加入者配成一对；同一身份重复认领时以最新的地址为准，用于掉线重连。
- **API 下发**：加入的响应带 `relay: { address: "IP:端口", ticket }`（加入者那张）；房主轮询返回的每个加入请求带同样结构（房主那张）。测延迟的探测加入不发。
- **私钥**：Secret Manager `LAUNCHER_RELAY_PRIVATE_KEY`，PKCS#8 PEM。
- **公钥**（SPKI PEM，中转用它验签）：`MCowBQYDK2VwAyEA5jg6ifgT3iL6fUxsjeymZy9x4Ni1BnPTrMocZfhxrpc=`

## 统计与提示

- **连通所走的路新增 `relay`**：`launcher_room_events.path` 原有字段，不加列。
- **15 秒仍未连通的提示改成「连接失败，请稍后再试」**：有中转后还连不上，多半不是玩家网络的问题，让玩家换网络不对症；三种语言一起改。

## 上线顺序

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | 本设计 + API 发通行证 | 中转地址先不配，不发通行证，对现有玩家无影响 |
| 2 | 中转程序与部署（server 仓库） | 部署到上海按量计费云服务器；上线后在 API 配上中转地址 |
| 3 | 启动器 | 中转候选、`--relay-only`、统计、提示文案、协议版本 |
| 4 | 实机测试 | 加入者带 `--relay-only` 打一整局，记录中转延迟 |
| 5 | 启动器 0.5.0 发版 | 与阶段 3 的改动一起 |
| 6 | 换年付服务器 | 运行几天后按中转统计选轻量服务器套餐，改 API 地址；旧机器留到正在走中转的游戏结束再销毁 |

## 不做

- **限速、单 IP 上限**：只有持有效通行证的人能用中转，即真正加入了房间的人；出现滥用再加。
- **加密转发内容**：游戏数据本来就是明文 UDP，打洞时也一样。
- **中转与 API 互通**：通行证自带证明，不需要。
