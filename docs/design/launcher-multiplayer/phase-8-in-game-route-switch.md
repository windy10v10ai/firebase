# 启动器联机 阶段 8：按游戏数据丢包在游戏中换路

> 状态：已完成，随启动器 0.7.1 发布，对应 windy10v10ai/game#2624。长期说明见 [启动器联机](../../../launcher/README.md#联机)，丢包字段见 [docs/api/README.md](../../api/README.md) 的 `launcher_room_events` 字段。

有玩家直连时启动器显示丢包 0%，游戏里收到的数据却丢了 38%：小而稀疏的 ping 能过，又大又密的游戏数据被丢。加上阶段 6 只在开局比一次，之后整局不换；30 秒没回包才重连，而 Dota 约 20 秒就断开游戏。

## 决定

- **丢包按游戏数据的序号统计，两个方向分开**：ping 测不出这类线路；状态行显示收、发两个方向，和 Dota 自己的显示对得上
- **一秒丢包 ≥ 10% 算坏秒，最近 10 秒有 6 个坏秒才考虑换**：偶发几秒的抖动不值得换线
- **换不换沿用阶段 6 的得分，另一条要好出 30 ms**：只看到在用的线路变差，不代表另一条更好
- **直连与中转对称，两次换路至少隔 60 秒**：中转也会变差，规则不分方向
- **换过去后用游戏数据看 10 秒，比换之前还差就换回并锁定本房间**：另一条只靠 ping 打分，可能同样看走眼；最多来回一次
- **10 秒没回包就重连，原来走中转的优先回中转**：赶在 Dota 断开前接回
- **阈值由 API 下发，不下发就不在游戏中换路**：调参数只部署 API

## 不做

- 换到另一台中转：房主只在一台中转上认领，要改房主端；中转整台挂掉时 10 秒重连会回到直连
- 默认强制走中转：直连正常的玩家延迟会变高
- 「优先中转」勾选框：自动换路覆盖了要它的场景，测试用的 `--relay-only` 参数保留

## 后续事项

- 上线后看 `connection_quality` 的 `data_loss_down_pct` / `data_loss_up_pct`，核实直连单向丢包有多常见、换路后是否好转，再调阈值
