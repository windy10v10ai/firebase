# 本地主机策略 阶段 1a：后端

> 状态：已完成。对应 issue [#1105](https://github.com/windy10v10ai/firebase/issues/1105)。放行规则见 [docs/api/README.md](../../api/README.md) 的「路由与认证」，限额取值见同节「本地主机来源的限额」。策略总纲见 game 仓库 `docs/local-host/README.md`（windy10v10ai/game#2406），game 侧改动见 windy10v10ai/game#2407。

Dota 2 官方自定义游戏服务器故障，玩家只能用本地主机开局。本地主机拿不到官方服务器密钥，临时用打包进地图的 API key 顶替，地图一解包 key 就泄露。这一批的做法是「放开低风险接口 + 给能产出或消耗资源的接口加限额」。

## 决定

- **守卫从「比对 key」改成「解析来源 + 按路由声明放行」**：原先需要本地 key 的路由只能挂 `@Public()` 彻底关掉守卫、再在 handler 里手写一句判断兜底，本批要新放行 7 条接口，手写会变成 10 处，漏写一句就是裸奔；改完漏挂装饰器的后果反过来是「本地 key 被拒」
- **`@Public()` 留给三个收款平台的 webhook**：它们不带 key，靠签名或 token 验证
- **加点、洗点、觉醒、随机觉醒、点赞举报继续对本地 key 拒绝**：这些改的是账号养成状态，留给阶段 2 的网站用 Steam 登录承接
- **`GET /game/start` 遇到未知 key 由返回 200 空数据改为 401**：与 `POST /daily-task/refresh` 的现有行为对齐
- **GA4 配置改成只排除未知来源，本地 key 也下发**：接受这期间混进假数据，否则本地这段完全没有统计
- **不做数据迁移**：改名前的两个日期与计数字段上线后不再被读取，等于上线当天所有人的当日额度重置一次
- **后端先上，game 后上**：旧地图在本地不会调这些接口，先上没有副作用，也允许按接口拆成多次部署

## 不做

- **未支付订单数单独统计**：每日 10 次的计数只增不减，堆积的未支付订单必然已经计入，效果等价还省一个 Firestore 复合索引
- **查单接口限流**：它是前端两秒一次的轮询，客户端已经做了并发抑制
