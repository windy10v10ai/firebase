# 每日任务 Phase1 重新设计

> 状态：已完成。前后端分工与长期规则见 [docs/api/README.md](../../api/README.md) 的「每日任务」与「每日任务数值」。

最初的实现把个人任务、全服共同任务、连续完成、付费刷新一次做完：7 个集合、开局十人 40 多次读、一套寄生在开局上的结算状态机、四套版本号，服务端还要把客户端算过的达标再判一遍。这次把范围收到个人任务，整套重新设计。

## 决定

- **只做个人任务，连续完成与全服共同任务往后排，付费刷新直接删掉**：它们带来的状态机与集合是复杂度的主要来源，不为后续阶段预留字段
- **候选确定性重算、不落库**：省掉冻结候选与版本号，整个功能只剩一个集合，文档数等于玩家数
- **判定与计分交给客户端，服务端只记轮次**：结算本来就信任客户端算的积分，单独在任务上校验防不住什么
- **每轮固定 1★ / 2★ / 3★ 各一个**：独立掷星有约 7% 的轮次难度维度失效，全 3★ 时玩家会卡在这一轮
- **用地图名而不是难度倍率判断是否生效**：倍率会放行 custom 地图，而且它衡量的是积分缩放，不是指标好不好拿
- **指标收到 10 个，全部从 `PlayerResource` 读**：去掉要逐事件采集的控制时长与伤害分类，不让每日任务拖慢后期

## 不做

- 全服共同任务与连续完成：等个人任务跑稳再说
- 付费刷新：后来改成每轮一次的免费刷新，见 [refresh-design.md](refresh-design.md)
- 结算重放的幂等保护：属于基础结算的既有问题，不在这里修
