# 批次 2：登录入口交互

> 状态：已完成。`/my/*` 门禁与页面清单见 [docs/web/README.md](../../web/README.md) 第 3 节，鉴权链路见 [phase-2-steam-login.md](phase-2-steam-login.md)。

玩家多数不从首页进来，而是在游戏里点「前往网站」直接落到功能页，所以**未登录状态下的功能页面**才是最主要的登录入口，头部按钮是次要入口。

## 决定

- **不做独立登录页**，头部按钮点一下直接跳 Steam：参考站 steamdb 要点两次才进得去
- **文案写明「通过 Steam 登录」并配图标**，不只放在悬停提示里——手机上没有悬停。跳过去之后 Steam 自己的页面会显示请求登录的站点域名并注明与 Valve 无关，所以我们这边不用长篇论证可信度，重点放在为什么要登录、网站拿到什么
- **按钮自绘，不用 Valve 提供的图**：官方文档写的是 request 不是 must，官方图是蓝色英文，放进深色界面里很突兀。保留 Steam 图标和字样、不伪装成官方页面即可
- **未登录时原地显示登录面板，不跳登录页**：跳 `/login?next=...` 并不省代码（登录 UI 都只写一份组件），却多一次导航和一层「回哪去」的状态。原地显示时地址栏始终是玩家想去的页面，从游戏里跳进来的人尤其不会困惑
- **门禁集中在 `/my/*` 一个 catch-all 页面**，以后加新的玩家页面这里一个字都不用改；`/profile/<id>/*` 自己不判断登录，一律拿 URL 里的 id 请求接口，按 401 / 403 分流
- **不用 Next 的括号路由组**：括号是给「分组但 URL 不体现」准备的，这里 URL 自己已经把公开与私有分开了
- **登录按钮在被点击的那一刻记下当前地址**：一条规则同时覆盖「直接访问受保护页面」和「在任意页面点头部按钮」两种情况
- **`next` 放查询参数而不是 `sessionStorage`**：不依赖浏览器存储，换标签页打开也不丢；它参与 OpenID 签名，中途被改过核对会失败。回调页校验它必须以单个 `/` 开头，挡掉 `//evil.com` 和带协议的绝对地址
- **跳回用 `router.replace`**，不在历史里留下回调页：玩家按返回键不会又登录一次。回调只能发起一次，openid 参数在 Steam 那边一次性有效
- **激活页不强制登录**：面板不出现，只在 Dota2 ID 输入框旁给一个「用 Steam 登录自动填入」链接
