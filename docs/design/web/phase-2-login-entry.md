# 批次 2：登录入口交互

> 上级文档：[网站总体设计](README.md) 的「页面与菜单」。本文只定一件事：**玩家在网站上从哪里、怎样进入 Steam 登录**。鉴权链路见 [phase-2-steam-login.md](phase-2-steam-login.md)。
>
> 头部按钮与回调页已上线，剩下门禁 layout 与登录面板。

## 一句话结论

**不做独立登录页。头部放一个写明「通过 Steam 登录」的按钮，点一下直接跳 Steam；需要登录的页面在未登录时原地显示一块「登录面板」，由路由组的 layout 统一控制，页面本身不写判断。按钮在被点击的那一刻记下当前地址，登录完回到这里。**

## 1. 约束

- **少点几下**。参考站 steamdb.info 要「头部 Sign in → 独立登录页 → 再点 Sign in through Steam」，两次才进得去。
- **点之前知道会发生什么**。直接跳到 steamcommunity.com 而没有任何说明，玩家会疑惑为什么要给 Steam 账号密码。
- **移动端可用**。悬停提示在手机上不存在，说明不能只放在 tooltip 里。
- **玩家多数不从首页进来**，而是在游戏里点「前往网站」直接落到属性或觉醒页面。所以**未登录状态下的功能页面**才是最主要的登录入口，头部按钮是次要入口。

按钮**自绘**，不用 Valve 提供的图：Steam 官方文档写的是 request 不是 must，steamdb 也是自绘；官方图是蓝色英文，放进深色金色的界面里很突兀。保留 Steam 图标和「Steam」字样，不伪装成 Steam 官方页面即可。

跳过去之后 Steam 自己的登录页会显示请求登录的站点域名并注明与 Valve 无关，所以我们这边不用长篇论证可信度，重点放在**为什么要登录**和**网站拿到什么**。

## 2. 头部按钮（已实现）

文案「通过 Steam 登录」，前置 Steam 图标，点击直接发起 OpenID 跳转，不经过中间页。`title` 悬停提示补一句「跳转到 Steam 官方页面登录，网站只获取你的 Steam ID」。窄屏只显示图标，保留 `aria-label` 和 `title`。

登录后按钮换成 `ID 12345678`，点击进 `/profile`，旁边一个退出。没有 Steam Web API key，拿不到昵称头像，先只显示 ID。

## 3. 门禁写在路由组的 layout

需要登录的页面放进 `app/(player)/`，组内 `layout.tsx` 是客户端组件，从 `useAuth()` 拿状态决定渲染什么。路由组的括号目录不进 URL，`app/(player)/property/page.tsx` 仍然是 `/property`。

| 做法 | 新增一个受保护页面要写什么 | 漏写的后果 |
|------|------|------|
| 每个页面自己判断 | 每个页面开头一段相同的三态判断 | 忘了写就直接渲染业务组件，未登录时请求 401、页面报错 |
| 路由组 layout 统一判断 | 把文件放进 `(player)/` 目录，页面本身一行都不写 | 放错目录，退化成上一行 |

选路由组 layout。顺带两个好处：组内页面之间跳转时 layout 不重新挂载，不会闪；玩家点「退出」时 layout 立刻切回登录面板，不用各页面自己处理。

三种状态都要画，顺序不能错：

- **加载中**：Firebase SDK 从 IndexedDB 恢复登录态需要一瞬间。这段时间显示骨架屏，不能显示登录面板，否则已登录的人每次刷新都会先看到一下「需要登录」。
- **未登录**：显示 `LoginPanel`，不渲染 `children`，业务组件不挂载，也就不会发请求。
- **已登录**：正常渲染 `children`。

门禁只能做在客户端：登录态在 Firebase SDK 手里，没有 cookie，Next 的 middleware 在服务端看不到。

## 4. 未登录时原地显示面板，不跳登录页

跳 `/login?next=/property` 并不省代码（登录 UI 都只写一份组件），却多一次导航、多一层「回哪去」的状态。原地显示的地址栏始终是玩家想去的页面，从游戏里跳进来的人尤其不会困惑。

`LoginPanel` 是 layout 在未登录时渲染的整块内容，页头页脚照常显示，只有正文区换成它，地址栏不变：

- 标题：「需要 Steam 登录」
- 为什么要登录：这个页面要修改你的账号数据，先确认你是账号本人。
- 拿到什么：只获取你的 Steam ID（就是 Dota2 ID），不读昵称、头像和游戏列表。
- 怎么确认安全：点按钮跳到 steamcommunity.com 登录，密码输在 Steam 官网，本站拿不到。已登录 Steam 的话点一下就回来了。
- 大号登录按钮，本身是 `<a href>`，JS 没加载也能点。

激活页不强制登录：面板不出现，Dota2 ID 输入框旁边给一个小的「用 Steam 登录自动填入」链接，走同一个跳转。

## 5. 登录后回到原页面（已实现）

**一条规则覆盖两种情况**：任何登录按钮在被点击的那一刻读取当前地址，把它拼进回调地址。直接访问受保护页面时，当前地址就是那个页面；在任意页面点头部按钮时，当前地址就是那一页。

回调地址形如 `/login/callback?next=%2Fproperty`，整条地址作为 `openid.return_to` 发给 Steam。

- `next` 放查询参数而不是 `sessionStorage`：不依赖浏览器存储，换标签页打开也不丢。`return_to` 参与 OpenID 签名，被中途改过核对会失败。
- 回调页校验 `next` 必须以单个 `/` 开头，挡掉 `//evil.com` 和带协议的绝对地址；不合规就回首页。
- 跳回用 `router.replace`，不在历史里留下回调页，玩家按浏览器返回键不会又登录一次。
- 核对失败显示错误和「重试」，重试即带着同一个 `next` 重新发起跳转。
- 回调只能发起一次：openid 参数在 Steam 那边一次性有效，重复核对必然被判无效签名。

## 7. 验收

- 从首页点头部按钮，一次跳转到 Steam，登录后回到首页，头部显示 ID。
- 直接打开属性页（模拟游戏内跳转），看到登录面板，点按钮登录后回到属性页并显示数据。
- 在觉醒页点头部按钮登录，回到觉醒页，不是回首页。
- 已登录状态刷新属性页，不出现「需要登录」的闪烁。
- 登录完成后按浏览器返回键，回到发起登录的页面，不会重新触发一次登录。
- 手机宽度下头部只剩图标，功能页面板完整可读。
- 把 `next` 改成站外地址，登录成功后回首页而不是跳出站。
