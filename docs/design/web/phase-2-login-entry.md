# 批次 2：登录入口交互

> 上级文档：[网站总体设计](README.md) 第 7 节批次 2。本文只定一件事：**玩家在网站上从哪里、怎样进入 Steam 登录**。鉴权链路（OpenID 核对、Custom Token、AuthGuard）在 `phase-2-steam-login.md` 里写，本文不重复。

## 一句话结论

**不做独立登录页。头部放一个写明「通过 Steam 登录」的按钮，点一下直接跳 Steam；需要登录的页面在未登录时原地显示一块「登录面板」，由路由组的 layout 统一控制，页面本身不写判断。按钮在被点击的那一刻记下当前地址，登录完回到这里。按钮自绘以匹配站点风格，悬停提示只作补充，不作为说明的唯一载体。**

## 1. 问题

登录只有 Steam 一种方式，入口要同时满足三点：

- **少点几下**。参考站 steamdb.info 是「头部 Sign in → 独立登录页 → 再点 Sign in through Steam」，从任意页面登录要点两次。
- **点之前知道会发生什么**。直接跳到 steamcommunity.com 而没有任何说明，玩家会疑惑为什么要给 Steam 账号密码。
- **移动端可用**。悬停提示在手机上不存在，不能把说明只放在 tooltip 里。

## 2. 参考与约束

### steamdb.info 的做法

头部右上角是 Steam 图标加 Sign in 文字的链接，指向 `/login/`。登录页从上到下依次是：

1. 站点 logo ＋ Steam logo，中间一个加号，一眼看出「本站接 Steam」。
2. 登录能得到什么：解锁更多功能。
3. 会拿到你的哪些信息：steamid、昵称、头像、游戏列表，括号里逐项列清楚。
4. 免责声明：与 Valve 无关；随时可删号删数据；用 cookie 维持登录。
5. 一个蓝色大按钮「Sign in through Steam」，Steam 字样前嵌一个 Steam 图标。
6. 一段「How can I verify this is legitimate?」：点按钮会跳到 steamcommunity.com；已登录 Steam 的话点一下就行，不用输密码；本站拿不到你的用户名和密码。

值得学的是 3 和 6 两段文案：**逐项说清拿到什么**、**点之前讲明跳去哪、密码给谁**。独立登录页多一跳，是它的缺点。

它的按钮是自绘的，不是 Valve 提供的图。

### Steam 官方要求

[Steam Web API 文档](https://steamcommunity.com/dev)在 OpenID 一节写的是 request（请求你用），不是 must：使用 OpenID 的网站，跳往 Steam 登录页的链接「请」使用它提供的按钮图，有大小两种尺寸。steamdb 用的就是自绘按钮，可见不是硬性门槛。

两种选法：用官方图省事、稳妥；自绘按钮能匹配站点的深色金色风格，也能写中文。**推荐自绘**：网站界面要参考游戏风格，一张蓝色英文图片放进去会很突兀；自绘时保留 Steam 图标和「Steam」字样，不伪装成 Steam 官方页面即可。

### Steam 登录页自带的说明

跳过去之后，Steam 的 OpenID 登录页会显示请求登录的站点域名，并注明该站点与 Valve 无关。玩家在 steamcommunity.com 上输密码，这是 Steam 玩家熟悉的流程。所以我们这边不用像 steamdb 那样单开一段讲可信度，一句话带过即可，重点放在**为什么要登录**和**网站拿到什么**。

### 玩家从哪进来

多数玩家不是从首页逛进来的，而是在游戏里点「前往网站」直接落到属性或觉醒页面。这决定了**未登录状态下的功能页面**才是最主要的登录入口，头部按钮是次要入口。

## 3. 方案对比

| 方案 | 从任意页登录点几下 | 点之前有说明 | 移动端 | 实现量 | 备注 |
|------|------|------|------|------|------|
| A 独立登录页（steamdb 式） | 2 | 有 | 好 | 一个页面 | 多一跳；登录页只有一个按钮，内容太薄 |
| B 头部按钮直跳 Steam | 1 | 只有按钮文字和 tooltip | tooltip 失效 | 一个按钮 | 说明不足，单独用不行 |
| C 头部按钮弹出小面板再跳 | 2（不换页） | 有 | 弹层要适配 | 一个弹层组件 | 和 A 一样两下，只是不换页 |
| D B + 功能页未登录面板 | 头部 1；功能页 1 | 功能页有；头部靠文字 | 好 | 一个按钮 + 一个面板组件 | 面板本来就要做（未登录状态） |

方案 A 和 C 的「说明」都要玩家多点一下才看到。方案 D 把说明放在玩家必然经过的地方：从游戏跳过来落在功能页，未登录就看到面板，读完点一下走。头部按钮只服务于「已经知道要登录」的人，一下直跳。

## 4. 推荐：方案 D

### 头部按钮

- 文案「通过 Steam 登录」，前置 Steam 图标，不用只有图标的按钮。文字本身就是说明：点它会去 Steam。
- 加 `title` 悬停提示：「跳转到 Steam 官方页面登录，网站只获取你的 Steam ID」。桌面端多一层解释，手机上没有也不影响。
- 点击直接发起 OpenID 跳转，不经过中间页。
- 窄屏下只显示 Steam 图标，保留 `aria-label` 和 `title`。

### 门禁写在哪：路由组的 layout

需要登录的页面放进一个路由组 `app/(player)/`，组内 `layout.tsx` 是客户端组件，从 `useAuth()` 拿状态决定渲染什么。路由组的括号目录不进 URL，`app/(player)/property/page.tsx` 仍然是 `/property`。

| 做法 | 新增一个受保护页面要写什么 | 漏写的后果 |
|------|------|------|
| 每个页面自己判断 | 每个页面开头一段相同的三态判断 | 忘了写就直接渲染业务组件，未登录时请求 401、页面报错 |
| 路由组 layout 统一判断 | 把文件放进 `(player)/` 目录，页面本身一行都不写 | 放错目录，退化成上一行 |

选路由组 layout。它还有两个顺带的好处：组内页面之间跳转时 layout 不重新挂载，不会闪；玩家在页面上点「退出」，layout 立刻切回登录面板，不用各页面自己处理。

三种状态都要画，顺序不能错：

- **加载中**：Firebase SDK 从 IndexedDB 恢复登录态需要一瞬间。这段时间显示骨架屏，不能显示登录面板，否则已登录的人每次刷新都会先看到一下「需要登录」。
- **未登录**：显示 `LoginPanel`，不渲染 `children`，业务组件不挂载，也就不会发请求。
- **已登录**：正常渲染 `children`。

门禁只能做在客户端：登录态在 Firebase SDK 手里，没有 cookie，Next 的 middleware 在服务端看不到，拦不了。这也是主文档里「用户页面客户端渲染」的直接结果。

### 门禁做什么：原地显示，不跳登录页

| 做法 | URL | 刷新 / 收藏 | 导航次数 |
|------|------|------|------|
| 原地显示面板 | 停在 `/property` | 刷新还在原页面 | 0 |
| 跳到 `/login?next=/property` | 变成 `/login` | 刷新还在登录页，要靠参数才知道回哪 | 多一次 |

两种做法的登录 UI 都只写一份组件，跳登录页并不省代码，却多一次导航、多一层「回哪去」的状态。原地显示的地址栏始终是玩家想去的页面，从游戏里跳进来的人尤其不会困惑。

### 功能页未登录面板

`LoginPanel` 是上面 layout 在未登录时渲染的整块内容。页头页脚照常显示，只有正文区从业务内容换成这块面板，地址栏不变：

- 标题：「需要 Steam 登录」
- 为什么要登录：这个页面要修改你的账号数据，先确认你是账号本人。
- 拿到什么：只获取你的 Steam ID（就是 Dota2 ID），不读昵称、头像和游戏列表。这一条比 steamdb 短，因为我们没有 Steam Web API key，技术上也拿不到别的。
- 怎么确认安全：点按钮跳到 steamcommunity.com 登录，密码输在 Steam 官网，本站拿不到。已登录 Steam 的话点一下就回来了。
- 大号登录按钮，点击发起跳转。
- 按钮本身是 `<a href>`，JS 没加载也能点。

激活页不强制登录：面板不出现，Dota2 ID 输入框旁边给一个小的「用 Steam 登录自动填入」链接，走同一个跳转。

### 登录后回到原页面

**一条规则覆盖两种情况**：任何登录按钮在被点击的那一刻读取当前地址，把它拼进回调地址。直接访问受保护页面时，当前地址就是那个页面；在任意页面点头部按钮时，当前地址就是那一页。两种情况不用分开处理，`SteamLoginButton` 里一份逻辑。

回调地址形如 `/login/callback?next=%2Fproperty`，整条地址作为 `openid.return_to` 发给 Steam。

- `next` 放查询参数而不是 `sessionStorage`：不依赖浏览器存储，换标签页打开也不丢。`return_to` 参与 OpenID 签名，被中途改过核对会失败。
- 回调页校验 `next` 必须以单个 `/` 开头，挡掉 `//evil.com` 和带协议的绝对地址；不合规就回首页。
- 回调页是静态外壳，只做「读参数 → 调后端核对 → `signInWithCustomToken` → 跳回」，中间显示「正在登录」。跳回用 `router.replace`，不在历史里留下回调页，玩家按浏览器返回键不会又登录一次。
- 核对失败显示错误和「重试」，重试即带着同一个 `next` 重新发起跳转。

### 登录后的头部

没有 Steam Web API key 拿不到昵称头像，先只显示 ID：

- 头部按钮换成「ID 12345678」，点击进「我的」页面；旁边一个「退出」。
- 拿昵称头像是后话，不在批次 2 做。

### 组件清单

| 组件 | 用途 |
|------|------|
| `SteamLoginButton` | 封装跳转逻辑与 Steam 图标，大中小三档尺寸；头部、面板、激活页共用 |
| `LoginPanel` | 未登录整页面板：标题、说明、大按钮 |
| `(player)/layout.tsx` | 门禁：按三态渲染骨架、`LoginPanel` 或页面本身 |
| `AuthProvider` 中的 `useAuth()` | 提供「加载中 / 未登录 / 已登录」三态；主文档第 4 节已定 |

## 5. 验收

- 从首页点头部按钮，一次跳转到 Steam，登录后回到首页，头部显示 ID。
- 直接打开属性页（模拟游戏内跳转），看到登录面板，点按钮登录后回到属性页并显示数据。
- 在觉醒页点头部按钮登录，回到觉醒页，不是回首页。
- 已登录状态刷新属性页，不出现「需要登录」的闪烁。
- 登录完成后按浏览器返回键，回到发起登录的页面，不会重新触发一次登录。
- 手机宽度下头部只剩图标，功能页面板完整可读。
- 把 `next` 改成站外地址，登录成功后回首页而不是跳出站。
