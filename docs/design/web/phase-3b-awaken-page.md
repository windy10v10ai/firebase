# 批次 3b：英雄觉醒页

> 状态：已完成。路由 `/profile/<steamId>/awaken`，未登录的落点是 `/my/awaken`。同步脚本怎么跑见 [awaken-sync](../../../.claude/skills/awaken-sync/SKILL.md) 技能，数据本身见 `web/config/awaken.ts`。

本批包含觉醒页，以及把 game 的觉醒数据同步进网站的脚本与 skill——网站的数据文件得有人生成，所以不拆批次。

## 数据同步的决定

- **全量重生成，不做增量检测**：139 个输入文件全读一遍只要 70ms。game 有过只改数值不改文案的提交，而 18/38 条描述里带占位符，按「文案有没有改」判断会整个漏掉
- **git 历史用来解释，不用来决定**：产物头部记 game 的 commit SHA，下次同步时 `git log` 给出人能读的变更说明写进 PR；产物 diff 回答「变了什么」
- **只认 develop 上的提交**，判断的是提交位置而不是分支名——detached HEAD 拿不到分支名，而从 worktree 取数是常态。没有这道闸，从 feature 分支同步会静默产出指向可能被改写的提交的数据
- **占位符在生成时换成真实数值**，取值按六个 KV 文件的优先级查；最后那一项 `docs/reference/<版本>/heroes/*.txt` 不能省，炸弹人的攻击距离只在那里
- **英雄名跟游戏走**，包括 game 自己的改名（撼地者叫宇智波牛神、工程师叫茶神）：玩家在两边看到同一个名字
- **七项自检不过就停下不生成**，其中最关键的一项拿两个不同文件、两套正则互相印证 game 有没有漏同步；另一项的绝对下限保证正则同时失效时不会「两边都空所以通过」
- **取数和取图拆成两个命令**：取数纯离线、每次都跑；取图要联网、要临时装 sharp，只在缺图时跑

## 图片的决定

- **文件名带内容 hash**，配一年 immutable 缓存。版本目录要靠人记得改，还会让改一张图导致全部失效；hash 由脚本顺手算出，没有需要人记住的步骤。App Hosting 给静态资源的弱 ETag 实际只由文件大小决定，字节数相同的换图会一直发 304，hash 让内容一变 URL 必变
- **缓存头只能配在 `next.config.ts` 的 `headers()`**：`firebase.json` 那个 `hosting` 块是经典 Hosting，管不到 `web/`
- **立绘按高度拉满、横向居中裁边**，裁切封顶 1.35 倍，再宽就整体缩小不腰斩；人物不够高的贴底站地上，否则头顶天脚悬空
- **取景中心默认居中，偏了的在 override 表里点名**：按 alpha 重心自动找头部的两种算法都是修好一个带坏一个——Dota 立绘里道具体量和英雄本身相当，算法分不清哪个是人。默认居中行为可预测，出问题一眼知道改哪里
- **饰品图标从游戏客户端导出后进仓库**，按 `AbilityTextureName` 的完整路径存放：Steam CDN 只有原版图标；按完整路径存，饰品版和同名原版不会混淆
- 用原生 `<img>` 不上 `next/image`：本地静态文件已经是目标尺寸，过一道优化器只是白付 CPU

## 界面的决定

- **只讲永久觉醒，不讲觉醒石**：觉醒石是局内玩法，网站买不到，摆在购买页上只会让人问「在哪买」
- **卡片是立绘铺满的方块**，列数按屏幕档位给手机 2 / 平板 4 / 电脑 6 列。全站「条目卡 1 / 2 / 3 列」那条不适用于图墙——38 个按 350px 排要滚十几屏
- **整张卡是点击热区**：游戏内那个按钮只有 22px 高，触屏按不准；整张卡当热区就不用为凑 44px 触控目标把卡片撑大
- **详情和付费是同一个弹窗**：「看清楚买的是什么」和「选哪种积分付」本来就是一件事。游戏靠悬停 tooltip 看描述，触屏没有悬停，这个弹窗是必需的
- **三种状态沿用游戏的颜色语法**（未解锁紫描边、已觉醒金描边、限免绿角标），但**「指定英雄」「随机抽选」两个标签由游戏的金改成白色加粗**——网站的金已经归会员积分，再加一档金会串味
- **随机抽选渲染接口返回的候选，不是本地摇的那一份**：账号里已有未认领的候选时接口原样返回旧值，这正是游戏与网站共存的机制。接口没有 GET，页面加载时查不到待认领的候选；原样复用 game 文案就绕开了这点，不要自己写「重新抽取」
- **候选层的滚动动画照搬游戏**：轮播天然盖住了请求延迟，不是装饰
- **描述用约 40 行的白名单解析器**渲染成 React 节点，不用 `dangerouslySetInnerHTML` 加消毒：消毒是堵已知的洞，白名单只放行已知的东西，没有注入面
- **卡面不写技能名**，照 game 只放图标：加一行会让卡面变高、长技能名要缩字号，而且和游戏画面对不上；技能名放详情弹窗

## 不做

- 不做搜索、筛选、排序，也不做已觉醒分组——会打乱 game 的顺序，而顺序有意义（新的在前）
- 不做批量解锁：一次一个，失败范围最小
- 不显示每个英雄花了多少积分：接口有，但玩家不关心历史单价
- 不缓存、不做乐观更新：接口返回的就是新状态
- 不做定时同步：game 和网站同一个人维护，什么时候改了觉醒他自己知道
