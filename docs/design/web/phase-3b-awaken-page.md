# 批次 3b：英雄觉醒页

> 状态：已完成。路由 `/profile/<steamId>/awaken`，未登录的落点是 `/my/awaken`。同步脚本怎么跑见 [awaken-sync](../../../.claude/skills/awaken-sync/SKILL.md) 技能，数据本身见 `web/config/awaken.ts`。

本批包含觉醒页，以及把 game 的觉醒数据同步进网站的脚本与 skill——网站的数据文件得有人生成，所以不拆批次。

## 决定

- **同步每次全量重生成，只认 game develop 上的提交**：只改数值不改文案的提交也不会漏；从 feature 分支同步会产出指向可能被改写的提交的数据
- **自检不过就停下不生成**：game 漏同步或正则失效时宁可不出数据，也不出错的
- **英雄名跟游戏走**，包括 game 自己的改名：玩家在两边看到同一个名字
- **只讲永久觉醒，不讲觉醒石**：觉醒石是局内玩法，网站买不到
- **卡片是立绘铺满的方块，整张卡可点**：38 个按条目卡排要滚十几屏；游戏内那个按钮只有 22px，触屏按不准
- **详情和付费是同一个弹窗**：「看清买的是什么」和「选哪种积分付」是一件事，触屏没有悬停
- **颜色语法沿用游戏，但「指定英雄」「随机抽选」标签改成白色**：网站的金已经归会员积分
- **随机抽选显示接口返回的候选，候选层滚动动画照搬游戏**：账号里已有未认领的候选时接口原样返回，游戏与网站靠它共存

## 不做

- 不做搜索、筛选、排序与已觉醒分组：会打乱 game 的顺序，新的在前是有意义的
- 不做批量解锁：一次一个，失败范围最小
- 不显示每个英雄花了多少积分：玩家不关心历史单价
- 不做定时同步：game 和网站同一个人维护，改了觉醒他自己知道
