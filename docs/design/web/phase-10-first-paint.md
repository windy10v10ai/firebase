# 批次 10：首屏与加载态

> 跟踪 issue：#1176。长期有效的设计见 [docs/web/README.md](../../web/README.md)，写代码时的规约见 [web/CLAUDE.md](../../../web/CLAUDE.md)。

## 要解决的问题

打开网站时有两处闪烁：

1. **头部跳高**。登录按钮（36px）比头部其余元素高，判定登录态之前不渲染，判定完插进来，整页下移。
2. **先显示未登录，再翻成已登录**。首页对已登录用户依次出现三种高度：登录横幅 → 只有身份行的玩家卡 → 带统计数值的玩家卡。

根因只有一个：**首屏渲染时不知道用户是谁**。登录凭据在 Firebase SDK 的 IndexedDB 里，不随请求发给服务器；客户端也要等 SDK 下载、初始化，并且每次启动都要联网校验一次用户（SDK 内部无条件执行），才给出结论。这个往返无法优化，只能绕开。

## 效果

- 页面从第一帧起就是最终结构，之后只有格子里的字在变，布局全程不动
- 回访的已登录用户首屏直接看到账号控件和自己的玩家卡，不再闪一下登录横幅
- 数值没到时显示发亮的圆角骨架块，到了原位替换
- 站内跳转进玩家页同样如此：登录态跳转时已知，只有数据要等，走同一套骨架块

## 做法

把「不知道」拆成两类，各用各的手段：

| 不确定的是 | 手段 |
|---|---|
| **形状**：渲染登录横幅还是玩家卡 | 服务端读 cookie，首屏 SSR 就定 |
| **内容**：数值、将来的头像 | 容器 CSS 定死尺寸，数据没到时放骨架块 |

### 登录态：`player-uid` 提示 cookie

- Firebase `onAuthStateChanged` 是**唯一写入点**：有用户写 uid，没有就删。登录、登出、token 失效、别的标签页登出都走这一处
- 根 layout 用 `cookies()` 读，作为初始状态传给 `AuthProvider`；Firebase 恢复完照常更新，一致则页面不动
- cookie 缺失按未登录渲染
- 规格：非 HttpOnly、`max-age` 一年、`SameSite=Lax`。每次打开页面 Firebase 给出结论时都会重写，活跃玩家等于永不过期；过期了也只是退回按未登录渲染，Firebase 随即校正
- 本批次上线前已登录的玩家没有这个 cookie：第一次打开仍会像以前一样闪一次，同时补写 cookie，之后正常，不需要重新登录

**它不是凭据。** uid 本来就出现在 `/profile/<steamId>` 地址里；API 只认 Firebase ID Token，伪造这个 cookie 只能骗过自己浏览器的第一帧。不得拿它做任何鉴权判断。

### 删掉「加载中」这一态

登录态从三态（加载中 / 已登录 / 未登录）缩成两态。加载中原本兼管两件事：

- 渲染要不要出内容 → cookie 接管
- 请求能不能发（token 没恢复时发出去会拿到假 401）→ 下沉到 `apiFetch`，取 token 前 `await auth.authStateReady()`

于是各页面自己写的「等登录态再发请求」判断全部删掉。

### 登录按钮在服务端也能渲染

登录链接要拼 Steam 回调地址，原本读 `window.location.origin`，只能在浏览器里跑。改成根 layout 用 `headers()` 读 `host` 与 `x-forwarded-proto` 拼 origin 传下去。

不用构建期环境变量：同一份生产构建同时从 `windy10v10ai.com` 和 `prod--windy10v10ai.asia-east1.hosted.app` 访问，写死一个，另一个域名进来时 Steam 会拒绝回调。

### 加载态：一套 DOM，骨架块放在字段位置上

- 数据没到时直接渲染真实的卡片布局，只把数值位置换成骨架块（卡片内的小灰条）；不再用替换整页的占位
- 骨架块高度等于真实文字行高，宽度随意
- 用 Tailwind `animate-pulse`，封装成 `app/components/ui/skeleton.tsx`，不引第三方库
- 失败态（401 / 403 / 404）仍整块换成登录面板或错误说明，那是用户预期内的切换

替换整页的占位（现在的 `PageSkeleton`）的问题是它自己一套布局，必须手工与真实页面保持同尺寸：它是单列两块大灰条，`/profile` 真实是两栏六张卡，数据到了整页一换照样跳。

将来的 Steam 头像同理：固定尺寸的圆形容器，图片没到或加载失败时显示现有的人形图标，容器尺寸不变。

首页玩家卡 ID 下方的会员行始终占位：窄屏状态与有效期各一行，宽屏并排一行，都不折行、放不下时截断；加载中与非会员都只留白，这一行可能本来就没有内容，放骨架会预告不存在的内容。没选的两种：挪进数值网格（非会员要多看一行「未开通」）；非会员到达后收起（多数玩家不是会员，照样会跳）。

身份行整行都是去个人主页的链接，窄屏右侧只留箭头。375 宽下身份行去掉头像只剩约 250px，「个人主页」文字链接占掉 76px 后放不下 10 位 ID；缩小 ID 字号在 360 宽仍会折行。

### 字体：来不及就不换

网站字体 Noto Sans SC 按字形拆成上百个分片、不预加载，首屏先用系统字体画，下载完再换上。系统字体字形更宽，换的一瞬间整页文字缩一下，标题最明显。`next/font` 的 `display` 用 `optional`：约 0.1 秒内没到就本次沿用系统字体，缓存后的访问直接用 Noto Sans SC。

代价是首次访问看到系统字体；分片按页面用到的字取，某页含有未缓存分片的字时，同一页里可能混用两种字体。

### 断点：手机、平板、电脑三档

| 档位 | 宽度 | 前缀 |
|---|---|---|
| 手机 | < 768 | 无前缀 |
| 平板 | 768–1023 | `md:` |
| 电脑 | ≥ 1024 | `lg:` |

只用 `md:` 与 `lg:`。平板和手机一样是触控操作，靠鼠标才成立的东西（较矮的按钮、常驻的次要按钮、完整的账号文字）到电脑这一档才出现；平板比手机多的只是宽度，够放横排导航与两列内容。

现状混用 `sm:`（640）、`md:`、`lg:` 三个断点且含义不统一，640 这个切换点也不在验证宽度里。实测英文已登录、10 位 ID 在 768 时，横排导航与 ID 文字同时挤进头部，只剩约 12px，处在溢出临界（系统字体下把汉堡按钮挤出视口 1px）。

卡片网格同样按三档：手机 1 列、平板 2 列、电脑 3 列。属性页原为 1280 起三列（#1181），1024–1279 只有两列，单卡被拉到 490–618px，与「单卡宽度保持在手机单列附近」的初衷相反；改到 1024 起三列后，各宽度单卡落在 323–489px，1024 下最长的按钮文字「Not enough points」也不溢出。

属性卡的「满级」标签从名称后面移到右侧数值上方。英文长名称加标签在 375 手机上就会把标签挤到第二行，同一排卡片的进度条随之错位，与列数无关。没选的两种：放进等级那一行，英文会把等级说明撑成两行；去掉标签，满级仍有进度条与底部「已满级」表达，但扫一眼卡片顶部认不出哪些已满级。

## 分两个 PR

**PR 1：头部与首页**

- cookie 数据流、登录态缩两态、`apiFetch` 等 SDK 就绪
- 登录链接的 origin 由服务端传入，经 `useAuth().loginUrl()` 拼接；登录按钮、激活页、登录回调页共用
- 头部：账号位永远有控件；那一行加最小高度兜底
- 首页：统计网格常驻，数值位置放骨架块，请求失败显示横线；登录横幅去掉占位
- `/my/*`：未登录显示登录面板，已登录只做跳转、不渲染占位
- `/profile` 与属性页：去掉「等登录态恢复再发请求」的判断，整页占位留到 PR 2
- 首页玩家卡的会员行始终占位；身份行整行可点，窄屏只留箭头
- 头部与菜单文案统一：中文横排「个人主页」，英文菜单「Attributes」、首页卡片「Skills & Items」
- 头部账号控件的 ID 文字与退出按钮到电脑宽度（≥ 1024）才显示，平板与手机一样只留图标、退出在菜单里
- 字体加载改为 `optional`
- 新增骨架块组件

**PR 2：玩家页结构直出与断点统一**

- `/profile` 与 `/profile/<id>/property` 加载中不再显示整页占位 `PageSkeleton`，直接渲染真实卡片布局
- 各卡片在数据没到时，把数值位置换成骨架块，数据到了原地替换
- `PageSkeleton` 因此没有使用者，删除
- 全站 `sm:` 迁到 `md:`；按钮高度的 `md:min-h-10` 迁到 `lg:`，平板保持 44px 触控高度
- 卡片网格统一为手机 1 列、平板 2 列、电脑 3 列；属性页 `xl:grid-cols-3` 改为 `lg:grid-cols-3`，同步更新 `phase-3a-property-page.md` 的列数说明
- 属性卡「满级」标签移到右侧数值上方
- 断点用法与验证宽度写进 `web/CLAUDE.md`，三档各呈现什么写进 `docs/web/README.md`

## 验收

- 375 / 768 / 1280 三档宽度，登录与未登录各一次，用 `PerformanceObserver` 收集 layout-shift，首屏到数据加载完 CLS 为 0
- 已登录用户首屏 HTML（禁用 JS 抓取）里已有账号控件与玩家卡
- 三个生产域名下登录回调都能跳回

## 不做

- **API 数据缓存**。HTTP `Cache-Control` 与「加点后立刻看到新值」冲突；应用层 stale-while-revalidate 有价值但不急，另见 #1175
- **服务端会话（HttpOnly session cookie + Admin SDK）**。服务端不碰用户数据，只需知道渲染哪套形状，一个 uid 足够
- **Firebase 自带的 `browserCookiePersistence`**。它把真凭据写进 cookie，需要配套代理路由并每秒轮询，为「服务端代表用户取数据」设计，这里用不上
