# 批次 10：首屏与加载态

> 状态：已完成。长期设计见 [docs/web/README.md](../../web/README.md) 第 4 节「加载态」「屏幕档位」，写代码时的规约见 [web/CLAUDE.md](../../../web/CLAUDE.md)「加载态」「断点」。

登录凭据在 Firebase SDK 的 IndexedDB 里，不随请求发给服务器；SDK 每次启动还要联网校验一次才给结论。这个往返无法优化，只能绕开——不绕开时头部登录按钮判定完才插进来、整页下移，首页对已登录用户依次出现三种高度。

## 决定

- **把「不知道」拆成形状和内容两类**：渲染登录横幅还是玩家卡由服务端读 `player-uid` 提示 cookie 决定，数值这类内容由容器定死尺寸、放骨架块
- **提示 cookie 不是凭据**：uid 本来就出现在地址里，API 只认 ID Token，伪造它只能骗过自己浏览器的第一帧。过期了也只是退回按未登录渲染，Firebase 随即校正
- **登录态只剩两态**：原先「加载中」兼管的「请求能不能发」下沉到 `apiFetch`，取 token 前等 SDK 就绪，否则 token 没恢复时发出去会拿到假 401
- **登录链接的 origin 由根 layout 从请求头拼**，不用构建期环境变量：同一份生产构建同时从 `windy10v10ai.com` 和 App Hosting 默认域名访问，写死一个，另一个域名进来时 Steam 会拒绝回调
- **加载中渲染真实布局，不做替换整页的占位组件**：占位组件是第二套布局，要手工与真实页面保持同尺寸，数据到了整页一换照样跳
- **可能本来就为空的位置只留白，不放骨架**：骨架块预告「这里马上有内容」，内容可能不存在时会误导。非会员的会员行就是这类
- **字体 `display: optional`，来不及就本次沿用系统字体**：Noto Sans SC 按字形拆成上百个分片、不预加载，中途换字体会让整页文字缩一下。代价是首次访问看到系统字体
- **断点定为手机 / 平板 / 电脑三档**，平板按触控设备对待：原先混用 `sm:` 且含义不统一，640 这个切换点也不在验证宽度里。实测英文已登录、10 位 ID 在 768 时头部只剩约 12px 余量，处在溢出临界
- **卡片网格改到 1024 起三列**：属性页原为 1280 起，1024–1279 单卡被拉到 490–618px，与「单卡宽度保持在手机单列附近」的初衷相反

## 不做

- **不做 API 数据缓存**：HTTP `Cache-Control` 与「加点后立刻看到新值」冲突；应用层 stale-while-revalidate 有价值但不急，另见 #1175
- **不做服务端会话**：服务端不碰用户数据，只需知道渲染哪套形状，一个 uid 足够
- **不用 Firebase 的 `browserCookiePersistence`**：它把真凭据写进 cookie，需要配套代理路由并每秒轮询，为「服务端代表用户取数据」设计，这里用不上
- **不加路由级 `loading.tsx`**：跳转时显示整页 fallback，等于第二套布局
