# 批次 8a：首页

> 首页现在是「标题 + 创意工坊 / GitHub 两张卡 + 关于项目」。登录功能上线快一年了，首页一个字没提，玩家不知道网站能看数据、能加点。这一批把首页改成「说清楚能干什么 + 把人送进对应页面」。设计稿见 [Claude Design 画布](https://claude.ai/code/artifact/f2da5c3e-41a9-4af3-a0d5-3aba73209157)。

## 一句话结论

**删掉「关于项目」，在标题下方加两块：一块讲登录后能看什么并给登录入口，一块是主要页面的卡片导航。两块的取值全部来自 [phase-7-visual-style.md](phase-7-visual-style.md) 的 token，不引入图片资源。**

## 1. 改什么

| 区块 | 现状 | 改成 |
|------|------|------|
| 标题 | 居中一行 | 不动 |
| 关于项目 | 一段介绍文字 | 删除，`home.about` 两个 key 一并删 |
| 登录引导 | 无 | 新增，见第 2 节 |
| 主要页面 | 无 | 新增，见第 3 节 |
| 创意工坊 / GitHub | 两张卡，`max-w-2xl` | 内容不变，宽度跟着统一到 `max-w-4xl` |

**内容宽度统一成 `max-w-4xl`（896px）。** 新增两块要放下左右分栏和三列卡片，`max-w-2xl`（672px）不够；只加宽新块会让页面一宽一窄。四块用同一个宽度，页面才是一根竖线。

## 2. 块 1：登录引导

一块通栏卡片。**数据面板铺在背景里，文案与登录按钮压在上面**，不是左右分栏——分栏会让右半边的示意图看起来像一张要读的图，压在背景里才是它该有的分量。

### 未登录

- 背景：12 格数据面板，四列三行。内容是勇士等级、会员等级、可用积分、场次、胜率、行为分、每日签到、三项属性数值、已觉醒英雄。
- 遮罩：`linear-gradient(90deg, …0.97 0%, …0.95 46%, …0.62 72%, …0.45 100%)`，左边压到看不清、右边留出面板。
- 正文压在左半边：标题、一句说明、Steam 登录按钮（`SteamLoginButton size="large"`）、按钮旁一句「密码输在 Steam 官网，本站只拿到你的 Steam ID」、四个「接下来会加入」的小标签。

**背景面板是静态示意，不请求接口。** 它只是「登录后能看到这些」的样子，数值写死在组件里，整块挂 `aria-hidden="true"`，读屏只读左边的文案。用 div + token 画，不做成图片：没有资源要维护、不占体积、换 token 时自己跟着变、文字仍是文字。

面板里的数值取自 game 仓库 `game/scripts/npc/npc_items_modifier.txt` 的逐级取值，写真实的而不是随手编，玩家一眼能对上游戏里的数：

| 项 | 等级 | 值 |
|------|------|------|
| 冷却时间 | 3 | −12% |
| 移动速度 | 2 | +50 |
| 额外视野 | 2 | +100 |

胜率 75.2%，行为分 110。**行为分用绿色**：game 的 tooltip 里 ≥110 属于金色 ×1.1 档，这里不跟——金色在本站专指会员，行为分挂金色会被读成会员权益。

### 登录后

同一块换成玩家自己的数据，**结构照个人主页的身份卡**，玩家在两处看到的是同一种排版：

| 行 | 内容 |
|------|------|
| 身份 | 头像、`ID <id>`、会员状态 |
| 数值 | 勇士等级、会员等级、可用勇士积分、可用会员积分，两列四项 |
| 引导 | 可用属性点、已觉醒英雄、每日任务，整行可点 |

三条约束：

- **会员状态是纯文字**，金色等级加一句灰色有效期，不放「前往订阅」按钮。首页这块的任务是引导去看数据，订阅入口在块 2 的会员卡和会员页，同一屏放第三个订阅按钮是噪音。
- **只放最常见的几项**。战绩那一长串留在个人主页，首页给不出增量信息。
- **引导行有值才显示**。可用属性点为 0 时整行不渲染——摆一个「0 去加点」是反效果。每日任务显示 `n/3` 加一条进度条，点进任务页。

头像现阶段是占位圆。真头像要 Steam Web API key，排在批次 9，届时只换这一个元素。

## 3. 块 2：主要页面

一张 `Section`，里面六张卡，桌面两行三列，窄屏一列：

| | 第一列 | 第二列 | 第三列 |
|------|------|------|------|
| 第一行 | 个人主页 | 属性加点 | 英雄觉醒 |
| 第二行 | 会员订阅 | 每日任务 | 技能与物品 |

**没实现的页面也要出现，做成虚线卡加「即将上线」，不可点。** 这与 [README](README.md) 里「页面没实现前，菜单项不放出来」不冲突：那条约束的是头部菜单——玩家点菜单是要去干事，落到空页会以为网站坏了。首页这一块本来就在讲「今后会加入什么」，把没上线的列出来正是它的内容。两者的区别是能不能点：虚线卡没有 `href`。

页面上线时把对应卡换成实线可点，一张一张换，不用等齐。

## 4. 实现步骤

分四步，**第一步就能上线**，后三步各自挂在别的批次上，不单独排期。

### 第 1 步：本批次

1. 删 `web/app/page.tsx` 里的关于项目 `Section`，删 `messages/zh.json`、`messages/en.json` 的 `home.about`
2. 新增块 1：未登录与登录后两个分支，按 `useAuth()` 的状态切；登录后的数据走已有的 `fetchPlayerInfo`，四项数值和会员状态它已经返回，不用加接口
3. 新增块 2：六张卡，能点的只有个人主页与会员订阅
4. 三块内容宽度统一 `max-w-4xl`
5. i18n 补齐 zh / en

登录后的三条引导行**这一步先不做**，数据还不齐：可用属性点要 `include=property` 和 `usedLevel`，已觉醒英雄的计数接口没有，每日任务的后端在 [#1040](https://github.com/windy10v10ai/firebase/pull/1040)。

### 第 2 步：跟 3a 属性页一起

`fetchPlayerInfo` 加 `include=property`，算出可用属性点，加第一条引导行；块 2 的属性加点卡换成可点。

### 第 3 步：跟 3b 觉醒页一起

加已觉醒英雄的引导行与可点卡片。计数接口若没有，读觉醒页已经要拿的那份数据即可，不为首页单开一个。

### 第 4 步：每日任务上线后

加 `n/3` 进度条的引导行与可点卡片。依赖 [#1040](https://github.com/windy10v10ai/firebase/pull/1040) 合并并给查询接口挂 `@AllowWeb()`。

技能与物品未排期，那张卡一直是虚线。

## 5. 不做什么

- **不给块 1 的背景面板配图**。理由见第 2 节。
- **不做「最近一局」「排行榜」**。前者后端没有单局查询，后者整块还没定。
- **不动头部与页脚**。头部是批次 2g 刚定的，这一批只碰 `web/app/page.tsx` 与它引用的组件。
