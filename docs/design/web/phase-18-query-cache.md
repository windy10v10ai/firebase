# 批次 18：数据缓存（TanStack Query）

> 状态：设计已定，待实现。实现时把下文「分档」「写操作与失效」两节作为长期规范同步进 [docs/web/README.md](../../web/README.md)，写代码的规约进 [web/CLAUDE.md](../../../web/CLAUDE.md)。

网站每进一页都要重新请求、重新显示骨架屏，站内来回跳转也一样；约 11 个组件各自手写「发请求 + 加载中 + 失败 + 防卸载后更新」，每处二三十行、写法几乎相同。目标三件事一起解决：站内跳转更快、少发重复请求、取数据的代码更好写。

## 决定

- **用 TanStack Query**：写操作后按 key 前缀批量失效、「必须显示实时数据」的页面各是一行配置。没选 SWR，因为它没有新鲜期与缓存回收的概念，这两点都要绕；没选自己写，因为去重、过期、切回窗口刷新、重试都得重造
- **缓存只在内存，刷新页面即清空**：不存 localStorage，避免刷新后数字从旧值跳到新值，也不用定旧数据的年龄上限
- **API 侧不加 HTTP 缓存头**：浏览器 HTTP 缓存清不掉，写操作后会看到旧值，F5 也救不回来
- **按数据性质分三档，页面只选档不填数字**：见下节
- **写接口调用方式不变，不改用 `useMutation`**：各页面已自己管理提交中状态，换写法只扩大改动
- **web 加 Vitest 单元测试**：只测缓存框架的纯逻辑，见「测试」

## 分档

| 档位 | 行为 | 数据 | 理由 |
|---|---|---|---|
| 实时 | 进页面必请求，离开即删缓存（`staleTime: 0`、`gcTime: 0`） | 属性加点、觉醒、会员（含付款）、每日任务 | 玩家来这些页面是为了操作，看到旧值可能按错；会员页涉及付款 |
| 短缓存 | 60 秒内不重新请求 | 首页玩家卡、个人主页、近期表现、雷达图、我的排名 | 主要用来看，一局结束才会变；切回窗口时过期的自动刷新 |
| 长缓存 | 30 分钟 | Steam 昵称头像、排行榜 | 昵称头像几乎不变；排行榜全体共用，晚几分钟无妨 |

不进缓存：登录回调、激活码、支付宝下单与查单、所有写操作。

缓存 key 集中定义。玩家相关的一律以 `['player', steamId, ...]` 开头，写操作后按这个前缀一次清掉该玩家的全部缓存；排行榜用 `['leaderboard']`。首页玩家卡与个人主页请求同一地址，共用一份缓存。

## 写操作与失效

写操作成功后做两件事：用接口返回的最新数据直接更新当前页的缓存，不再多请求一次；再让该玩家的其他缓存过期，正在显示的会后台刷新，没在显示的下次打开时再请求。

| 写操作 | 当前页 | 其他缓存 |
|---|---|---|
| 加点、洗点、觉醒、签到 | 用返回值更新 | 该玩家全部过期 |
| 支付宝付款成功 | — | 该玩家全部过期 |
| 刷新每日任务、抽觉醒候选 | 用返回值更新 | 不动 |

**换账号、退出登录时清空全部缓存**：公用电脑上下一个人不该看到上一个人的数据；同一地址本人看与别人看的返回可能不同，换账号后旧缓存不可靠。

## 失败与加载

- **重试**：4xx 不重试，结果不会变；5xx 与网络错误重试 1 次，挡偶发抖动
- **第一次加载**显示骨架屏，**第一次就失败**显示现有失败样式，都与现在一致
- **已有数据、后台刷新失败**：继续显示旧数据，不提示
- **切回窗口**：只刷新已过期的数据，保留 TanStack 默认开启的行为
- 个人主页失败时的统计事件保留

## 代码组织

- `web/app/lib/query-client.tsx`：Provider 与全局默认配置（重试规则、切回窗口刷新），放进根布局；换账号时在这里清空缓存
- `web/app/lib/queries.ts`：全站唯一定义缓存的地方，每类数据的 key、取数函数、档位，以及「让某玩家缓存过期」的函数。页面只写 `useQuery(xxxQuery(steamId))`
- 现有取数函数保留，作为 `queries.ts` 里实际发请求的一步；`steam-profile.ts` 里手写的去重删掉，写提示 cookie 的一步保留
- 不装调试面板

## 测试

**单元测试（Vitest，PR 1 引入）**：只测 `queries.ts` 与 `query-client.tsx` 的纯逻辑，直接用 `QueryClient`，不开浏览器。

- 各数据的 key 与档位配置
- 写操作后让该玩家缓存过期，不影响其他玩家与排行榜
- 换账号清空全部缓存
- 4xx 不重试、5xx 重试 1 次

CI 在 `.github/workflows/ci.yml` 的 `web-quality` 任务里加 `npm run test`。`web/CLAUDE.md`「校验」改成 lint + tsc + test + build，删掉「本目录没有测试框架」一句。

**浏览器实测（browser-verify，人工）**，同时记录请求次数：

1. 首页 → 个人主页：立刻显示，不再发 `/info` 请求
2. 属性页进出两次：每次都显示骨架屏、都发请求
3. 加点后回个人主页：属性点为新值
4. 首页签到后卡片立即更新，刷新页面不会再出现签到按钮
5. 退出、换号登录：看不到上一个账号的数据
6. 停留超过 60 秒后切回窗口：近期表现重新请求
7. 接口 404 只请求 1 次，500 请求 2 次

PR 正文给一组前后对比：「首页 → 主页 → 属性页 → 返回主页 → 排行榜」一趟的请求数。

## 不做

- **不在刷新页面后保留缓存**：数字跳变的观感问题与旧数据年龄上限都要额外设计，收益只在首次打开
- **不加 HTTP `Cache-Control`**：与写操作后立刻看到新值冲突
- **Playwright e2e 不进 CI**：页面行为照常人工验证
