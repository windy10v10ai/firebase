# 批次 18：数据缓存（TanStack Query）

> 状态：已完成。长期规范见 [docs/web/README.md](../../web/README.md) 第 4 节「数据缓存」，写代码的规约见 [web/CLAUDE.md](../../../web/CLAUDE.md)「数据请求与缓存」。

网站每进一页都要重新请求、重新显示骨架屏，站内来回跳转也一样；各页面各自手写一套发请求、加载中、失败的代码。目标是站内跳转更快、少发重复请求、取数据的代码更好写。

## 决定

- **用 TanStack Query**：写操作后按 key 前缀批量失效、实时页离开即丢缓存各是一行配置；没选 SWR，这两点它都要绕
- **缓存只在内存，刷新页面即清空**：不存 localStorage，避免刷新后数字从旧值跳到新值
- **不加 HTTP 缓存头**：浏览器 HTTP 缓存清不掉，写操作后会看到旧值
- **分实时 / 60 秒 / 30 分钟三档，页面只选档不填数字**：操作类页面要实时，看的页面按变化快慢分
- **雷达图、名次放长档**：变化慢，打完一局晚半小时更新可以接受
- **写操作只让「玩家状态」过期**：战绩、雷达图、名次、昵称头像网站上改不了，跟着过期只会白白多请求
- **每日任务切回窗口不刷新**：它的读取会顺带写库，页面上已有刷新按钮
- **写接口调用方式不变，不改用 `useMutation`**：各页面已自己管理提交中状态，换写法只扩大改动
- **web 加 Vitest**：只测缓存框架的纯逻辑，页面行为仍靠浏览器实测

## 不做

- **刷新页面后保留缓存**（#1175 原方案）：数字跳变与旧数据年龄上限都要额外设计，收益只在首次打开
- **Playwright e2e 进 CI**：页面行为照常人工验证
