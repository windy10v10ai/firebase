# 批次 3a：属性加点页

> 状态：已完成。路由 `/profile/<steamId>/property`，未登录的落点是 `/my/property`。26 条属性的名称、数值、分组与来源见 `web/config/properties.ts` 文件头的注释。

## 决定

- **属性表放在网站里，不做成接口下发**：这张表在 game 里本来就是硬编码的，为它加一个接口、改一遍游戏，成本远大于偶尔手工同步。改游戏数值时这份表要一起改
- **图标用 lucide，不扒游戏美术**：那是 Valve 的资源，26 张导出进仓库，版权和体积都不划算。选图标只看一眼能不能认出是哪条属性，抽象图标（闪电表示攻速、铁砧表示护甲）都换掉了——它们要玩家先在脑子里翻译一道
- **按生效方式分三组**，每组标题带一句规则说明：这一页最难讲清楚的就是「加了点为什么进游戏没数值」，分组本身就是答案
- **进度条一级一个颜色，从冰蓝逐级过渡到勇士紫**，不按分组分色：分组已经用标题说过一遍，颜色只表示加了几级。纯紫加满后整页只剩黑和紫；按分组或稀有度分色要玩家多学一层含义，也和「紫色只代表勇士」冲突
- **满级不换色**，只加标签并让整条微微发光：换色会让玩家以为满级是另一类属性
- **加减器是调整，升级按钮是提交，样式上分开**：按钮还没调整时是描边紫，调整过变实心紫，只有点数不够才变灰并写明「属性点不足」——灰色的默认态会被读成点不了。按钮定宽，文字从「升级」变成「升至 7 级」时两边都不移动
- **一次升满的四条照样画八格**，只是没有步进器：画成一格会让它在一排卡片里显得是另一种东西
- **生效规则放两层浮层，直接给英雄等级**，不让玩家自己乘 2——游戏内就是因为只说「每 2 级激活 1 级」才没人看懂
- **待加的预算是共享的**：所有卡片待加之和从可用属性点里扣，扣完全部变灰。否则会出现摆好几张卡、提交到第三张才失败
- **洗点的勇士积分改成固定 2000**：原来按等级浮动，等级越高洗一次越贵，高等级玩家反而不敢调整加点。**后端先发、游戏后发**——反过来的话游戏按 2000 判断按钮可用、后端仍按旧价扣，低等级玩家会点了按钮拿到 400。game 侧见 [windy10v10ai/game#2415](https://github.com/windy10v10ai/game/issues/2415)
- **文案一律以 game 的本地化为准**，包括 26 条属性名与「升至 X 级」；英文侧统一成 game 的 Attributes / Attribute Points，此前头部菜单、入口卡、页面标题三个名字指同一处

## 不做

- 不做批量提交：一次一条属性对应一次调用，失败范围最小
- 不做搜索、排序、筛选：26 条分三组已经够找
- 不缓存、不做乐观更新：接口返回的就是新状态，加点是低频操作
- 不显示累计积分和等级进度条：那是个人主页的事
