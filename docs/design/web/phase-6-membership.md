# 批次 6：会员页（状态与支付宝购买）

> 状态：设计中，范围已列出，画面未定。跟踪 issue [#1123](https://github.com/windy10v10ai/firebase/issues/1123)。总体规划见 [README.md](README.md)。

网站的 `/membership` 目前只有权益介绍和爱发电、Ko-fi 两个外链。游戏内的会员页已经能看会员状态、用支付宝扫码买会员和会员积分。这一批把游戏里那套搬到网站，网站成为买会员的第二入口。

## 游戏内现在有什么

game 仓库 `src/panorama/react/hud_main/pages/profile/tabs/member/`，分三个子页：

| 子页 | 内容 |
|---|---|
| 状态 | 皇冠 + 会员等级与到期时间；权益清单，普通会员分「基础 / 高级专属」两段，高级专属灰显可点去订阅 |
| 订阅 | 支付宝卡：1 / 3 / 12 / 36 个月四档，标每月单价与折扣；爱发电、Ko-fi 卡：外链订阅、外链商店、手动激活。普通会员额外提示「剩余时长按 0.6 倍折算为高级」 |
| 积分 | 支付宝卡：4000 / 12500 / 31000 三档，标比爱发电省多少；爱发电、Ko-fi 各三个外链按钮 |

- **平台顺序按语言**：中文是支付宝、爱发电、Ko-fi；其他语言是 Ko-fi、爱发电、支付宝。第三张默认折叠在「其他支付方式」后面
- **支付宝卡就地变成支付面板**：点档位 → 创建中 → 二维码 + 商品名 + 金额，每 2 秒查一次订单 → 成功（皇冠或积分图标 + 「已开通 N 个月」）/ 关闭 / 失败 / 网络错误 / 下单太频繁。成功后自动刷新玩家信息，玩家点「关闭」回到档位列表
- **价格写死在前端**，与 API 的 `alipay.constants.ts` 手动保持一致

## 网站要做什么

### 页面：`/membership` 一页做完

同一个地址，未登录与已登录看到的不同：

| 区块 | 未登录 | 已登录 |
|---|---|---|
| 我的会员 | 登录引导（登录后可扫码购买、查看会员状态） | 会员等级、到期日、可用会员积分；普通会员附 0.6 倍折算提示 |
| 会员权益 | 现有权益列表 | 同左，按当前等级标出已拥有 / 未拥有 |
| 购买 | 「会员 / 会员积分」两个分页；支付宝卡的档位按钮点了弹登录 | 同左，支付宝档位可直接下单 |
| 手动激活 | 现有「爱发电 / Ko-fi 手动激活」链接 | 同左 |

购买区沿用游戏的结构：每个分页三张平台卡，顺序按网站语言，第三张折叠。爱发电、Ko-fi 仍是外链，积分分页补上两边各三档的积分链接（网站现在只有订阅链接）。

### 支付宝下单

- 点档位弹出支付弹窗（手机贴底抽屉，与觉醒详情弹窗同一套），显示二维码、商品名、金额与状态；状态与游戏一一对应
- 弹窗开着时每 2 秒查一次订单，关掉就停。成功后重新拉玩家信息，「我的会员」当场更新
- **手机上多一个「打开支付宝付款」按钮**：手机没法扫自己屏幕上的码，二维码内容本身是 `qr.alipay.com` 的链接，手机上直接打开能拉起支付宝 App。要真机验证
- 二维码在浏览器本地渲染，不把付款链接发给任何第三方二维码服务

### 后端

| 改动 | 原因 |
|---|---|
| 新增网站专用的下单与查单路由，`:steamId` 放进路径，挂 `@AllowWeb()` | guard 只比对路径里的 `:steamId`，body 里的不校验；直接给现有路由挂 `@AllowWeb()` 等于能替别人下单。做法同每日任务的网站刷新路由 |
| 查单校验订单属于路径里的玩家 | 现有查单只按订单号读，不看归属 |
| 网站来源也计入每日下单次数 | 限额现在只对本地主机来源生效，网站来源完全不限 |
| 支付宝回调地址搬到 `api.windy10v10ai.com` | [api-entry](../api-entry/README.md) 留下的后续事项，这一批本来就要下真实订单，回调通不通当场能验 |
| e2e：用别人的 steamId 下单、查单被拒 | issue 验收项 |

## 需要拍板

1. **页面地址**：推荐保留 `/membership` 一页做完。菜单、首页、个人主页身份卡的「会员订阅」都指向它，未登录也要能看介绍；买会员只给自己买，地址里不需要 steamId。另一个方案是新开 `/profile/<steamId>/membership`，与属性、觉醒页同组，但会出现介绍页和购买页两个入口
2. **非中文用户看不看支付宝**：推荐照游戏，排第三、默认折叠
3. **网站下单限额**：推荐与本地主机共用同一份每日次数；付款成功后照常清零
4. **价格表放哪**：推荐网站也写死一份，与游戏一致；三处（API、游戏、网站）手动同步。不为此新开价格接口

## 不做

- **支付宝补单（输入交易号激活）**：接口还没实现，属于支付宝方案的第 5 步
- **支付宝回调丢失的对账兜底**：[api-entry](../api-entry/README.md) 已记为另开的事项
- **爱发电、Ko-fi 的站内支付**：两边都只能外链
