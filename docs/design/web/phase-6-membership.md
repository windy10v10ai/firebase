# 批次 6：会员页（状态与购买）

> 状态：设计中，范围与布局已定，画面未出。跟踪 issue [#1123](https://github.com/windy10v10ai/firebase/issues/1123)。总体规划见 [README.md](README.md)。

网站的 `/membership` 目前只有权益介绍和爱发电、Ko-fi 两个订阅外链。游戏内的会员页已经能看会员状态、用支付宝扫码买会员和会员积分。这一批把游戏里那套搬到网站，网站成为买会员的第二入口。

## 游戏内现在有什么

game 仓库 `src/panorama/react/hud_main/pages/profile/tabs/member/`，分状态、订阅、积分三个子页：

- **状态**：会员等级与到期时间、权益清单
- **订阅 / 积分**：各有支付宝、爱发电、Ko-fi 三张平台卡，顺序按语言，第三张折叠在「其他支付方式」后面。支付宝会员四档（1 / 3 / 12 / 36 个月），积分三档（4000 / 12500 / 31000）；爱发电、Ko-fi 是外链
- **爱发电链接在备注里带上玩家 ID**（`remark=<steamId>`），付款后自动到账；Ko-fi 链接带不了，要玩家自己在留言里填
- **支付宝卡就地变成支付面板**：创建中 → 二维码，每 2 秒查一次 → 成功 / 关闭 / 失败 / 网络错误 / 下单太频繁；成功后刷新玩家信息

## 决定

- **保留 `/membership` 一页做完**：菜单、首页、个人主页的「会员订阅」都指向它
- **会员与会员积分放在同一页，上下排列**：分成两个页面，玩家不一定会点到第二页去看
- **所有购买都要先登录**：支付宝下单离不开玩家 ID；爱发电登录后能把 ID 带进链接，Ko-fi 登录后能在旁边直接显示 ID 供复制。三家做法一致，玩家不用分辨哪家要登录
- **平台用一排切换标签选，不是每个区块各放三张平台卡**：会员、积分两块各放三张卡，页面会很长，同一个平台还要看两遍。选中一个平台后，会员和积分两块都显示这个平台的价格
- **平台顺序与折叠照游戏**：中文默认支付宝、爱发电，Ko-fi 折叠；其他语言默认 Ko-fi、爱发电，支付宝折叠
- **手机上也只提供扫码**：不做「打开支付宝」按钮
- **价格表在网站写一份**：与 API、游戏手动保持一致，不为此新开价格接口
- **网站下单与游戏内共用每日下单次数**

## 页面布局

从上到下四块，电脑与手机结构相同，手机只是改成单列：

```
┌ 我的会员 ─────────────────────────────────────┐  ← 高度固定，登录与否同尺寸
│ 皇冠  高级会员 · 到期 2026-12-31   可用积分 1200 │
│       （普通会员：购买高级后剩余时长按 0.6 倍折算） │
└───────────────────────────────────────────────┘
  会员权益（现有列表，按当前等级标出已拥有 / 未拥有）

  购买   [ 支付宝 ][ 爱发电 ]  其他支付方式 ›        ← 平台标签
  ┌ 会员 ───────────────────────────────────────┐
  │ [1 个月] [3 个月 -10%] [12 个月 -16%] [36 个月 -20%] │
  └─────────────────────────────────────────────┘
  ┌ 会员积分 ───────────────────────────────────┐
  │ [4000 积分] [12500 积分] [31000 积分]           │
  └─────────────────────────────────────────────┘
  手动激活：爱发电 / Ko-fi · 数据什么时候生效 ›
```

### 我的会员

- 已登录：会员等级、到期日、可用会员积分。普通会员的 0.6 倍折算提示放在这张卡里，不放在购买区
- 未开通会员或已过期：同一张卡显示「未开通会员」
- 未登录：同一张卡、同样高度，灰色皇冠加「登录后查看会员状态并购买」和登录按钮
- **不闪**：显示登录形态还是未登录形态，由服务端按 `player-uid` 提示 cookie 决定，已登录用户第一帧就是这张卡，数值位置放骨架块，等数据到了再填。卡里所有行一直都在，数据回来不会多出一行，页面也就不会跳。做法同批次 10，见 [phase-10-first-paint.md](phase-10-first-paint.md)

### 会员档位（多个月的优惠）

支付宝四档排成一行（手机上两列两行），每档一块：

- 大字是**每月单价**（¥26.80 / 月），下面一行是**月数与总价**（3 个月 · 共 ¥80.40）。扫码付的是总价，档位上必须能看到，游戏里只写了单价
- 有折扣的档右上角放折扣标签（-10%），样式与觉醒页随机卡的「-50%」一致
- 不标「推荐」「最划算」，只靠单价和标签对比

爱发电、Ko-fi 的会员只有一档（¥29.80 / 月、$4 / 月），会员这块只显示一个档位，旁边放「前往商店」链接。

### 积分档位

三档一行（手机单列），每档大字写积分数，下面写价格。支付宝档位加「比爱发电省 ¥20」这类标签；爱发电、Ko-fi 的档位就是外链。区块标题下写一句用途：会员积分可以提升会员等级、升级属性。

### 各平台点档位后

| 平台 | 已登录点档位 | 未登录点档位 |
|---|---|---|
| 支付宝 | 弹出付款弹窗（电脑居中，手机贴底抽屉，与觉醒详情弹窗同一套）：二维码、商品名、总价、状态。弹窗开着时每 2 秒查一次，关掉就停；成功后「我的会员」当场刷新 | 走 Steam 登录，登录完回到本页 |
| 爱发电 | 新窗口打开带 `remark=<steamId>` 的下单链接 | 同上 |
| Ko-fi | 新窗口打开商品链接；Ko-fi 标签下常驻一行「付款时在留言里填写你的 ID：xxx」加复制按钮 | 同上 |

未登录时档位照常显示价格，只是点了去登录，页面不会因为登录与否换一套样子。

需要补的外链：爱发电积分三档下单链接、Ko-fi 积分三档商品链接、两边的商店页，全部照抄游戏的 `src/panorama/utils/utils.ts`。

## 后端

网站新接口与现有接口共用同一套下单、查单逻辑：商品表、价格计算、创建订单、回调入账、下单限额都是同一份，返回内容也一样。差别只有三点：

| 差别 | 原因 |
|---|---|
| 玩家 ID 放在接口地址里，请求体里不再带 | 网站身份校验只核对地址里的 ID；ID 放在请求体里时校验不到，等于能替别人下单。做法同每日任务的网站刷新接口 |
| 查单时核对订单属于地址里的玩家 | 现有查单只按订单号读，不看是谁的 |
| 下单限额对网站来源也生效 | 现在只对游戏内（本地主机）来源计数；与游戏共用同一份每日次数 |

另外两件：

- 支付宝回调地址搬到 `api.windy10v10ai.com`，是 [api-entry](../api-entry/README.md) 留下的后续事项，这一批要下真实订单，回调通不通当场能验
- e2e：用别人的 steamId 下单、查单都被拒

## 不做

- **积分流水页**：后端没有流水记录，价值不够
- **支付宝补单、回调丢失的对账**：等玩家来问了再做
- **手机「打开支付宝」按钮**：先只做扫码
- **爱发电、Ko-fi 的站内支付**：两边都只能外链
