# 批次 6：会员页（状态与购买）

> 状态：设计已定，待实现。跟踪 issue [#1123](https://github.com/windy10v10ai/firebase/issues/1123)。总体规划见 [README.md](README.md)；购买区用品牌色的例外见 [design-system.md](../../web/design-system.md)「品牌色」。

`/membership` 目前只有权益介绍和爱发电、Ko-fi 两个订阅外链。游戏内的会员页已经能看会员状态、用支付宝扫码买会员和会员积分。这一批把那套搬到网站，网站成为买会员的第二入口。

## 页面结构

从上到下三块，电脑与手机结构相同，手机改单列：

1. **我的会员**：左边金皇冠、会员状态、有效期、Dota2 好友 ID 加复制；右边照个人主页等级卡的写法：会员等级、进度条、累计积分、可用积分
2. **会员权益**：现有 Section 原样保留，标题、说明与带 emoji 的列表都不改
3. **购买区**：付款方式标签 → 说明条 → 开通高级会员 → 分隔线 → 购买会员积分

页面底部保留现有的「忘记留言 ID 没有自动激活？手动激活」一行。

## 决定

- **会员与积分放同一页，上下排列**：分成两页，玩家不一定会点到第二页
- **所有购买都先登录**：支付宝下单离不开玩家 ID，爱发电登录后能把 ID 带进链接，三家做法一致。未登录时档位照常显示，点了走 Steam 登录，登录完回到本页
- **「我的会员」卡未登录也占同样位置与高度**：已登录用户第一帧就渲染这张卡、数值放骨架，由 `player-uid` 提示 cookie 决定形态，数据回来页面不跳；做法同 [phase-10-first-paint.md](phase-10-first-paint.md)
- **付款方式用三个标签切换，顺序固定为支付宝、爱发电、Ko-fi**：每个标签带游戏里的平台图标，副标题照游戏写「最优惠 · 扫码即付」「更多支付方式 · 人民币支付」「海外用户 · 美元支付」。默认选中按语言：中文支付宝、英文 Ko-fi、俄文爱发电
- **说明条只给操作引导**：支付宝「点档位出二维码，用支付宝扫码付款，付完自动到账」；爱发电「点档位跳转到爱发电付款，付完自动到账」；Ko-fi「付款时请在留言里填写你的 Dota2 好友 ID」加复制。爱发电与 Ko-fi 的说明条右侧放「付款时忘记填 ID？手动激活」。不在界面上解释平台限制，规约见 [web/CLAUDE.md](../../../web/CLAUDE.md)「界面文案」
- **点档位就付款，不做「先选档位再点付款」**：支付宝档位点了弹二维码，爱发电、Ko-fi 档位点了直接跳转。爱发电链接备注带 `remark=<steamId>`，链接照抄 game 的 `src/panorama/utils/utils.ts`
- **档位卡用中性底加 3px 平台品牌色顶条**：整块刷品牌色或渐变都显得廉价；顶条只回答「现在用哪家付」
- **档位卡两列排（B-1）**：左列「月数 / 共 ¥总价」，右列「划掉的原价 / 折扣标签 + 现价」，原价正好在现价上方，四张卡的价格右对齐成一列。会员卡高 84，积分卡高 96（左边放 game 的三档积分图）
- **原价取爱发电价**：会员 ¥29.80/月，积分 ¥98 / ¥280 / ¥648，与游戏里的折扣口径一致。价格照游戏写两位小数，不写「约」。爱发电、Ko-fi 自己的档位就是原价，不划线
- **折扣标签用 `discount` token 的描边样式**：与觉醒随机卡的「-50%」一致，贴在现价旁边，不放卡片右上角
- **会员档位按 1 / 3 / 12 / 36 个月从左到右排，不标推荐**
- **爱发电、Ko-fi 的会员只有一档，做成一条通栏**：左边「1 个月 / 按月订阅」与价格，右边「前往爱发电订阅 ↗」；高度与支付宝档位一致。不放商店链接，积分档位本身就是商店商品
- **电脑上三个标签切换时购买区高度不变**：标签、说明条、会员区、积分区各自定高。手机上会员档位一档一行，高度随平台变化，可以接受
- **支付弹窗**：电脑居中弹窗，手机贴底抽屉（与觉醒详情弹窗同一套），只做扫码，不做「打开支付宝」按钮。状态与游戏对应：等待扫码（二维码 2 小时有效）、成功、二维码过期（可重新生成）、下单太频繁。会员成功显示金皇冠与「已开通 3 个月高级会员」「有效期至」；积分成功显示该档积分图与「N 会员积分已到账」，不显示可用积分，免得玩家误以为总积分变少。成功后刷新「我的会员」
- **价格表在网站写一份**：与 API、game 手动同步，不开价格接口
- **网站下单与游戏内共用每日下单次数**

## API 改动

画面上的会员与积分数据来自现有 `GET /player/:steamId/info?include=member`，不加读取接口。支付宝下单要改：

| 改动 | 原因 |
|---|---|
| 现有下单、查单路由直接挂 `@AllowWeb()`，不新开路由、不核对归属 | 替别人下单等于送礼，钱由下单的人付；查单只返回订单号与状态，订单号猜不到 |
| 下单次数限额对 `WEB` 来源也生效 | 现在只对 `LOCAL` 计数 |
| 支付宝回调地址搬到 `api.windy10v10ai.com` | [api-entry](../api-entry/README.md) 留下的后续事项，这一批要下真实订单，当场能验 |

## 不做

- **积分流水页**：后端没有流水记录，价值不够
- **支付宝补单、回调丢失的对账**：等玩家来问再做
- **手机「打开支付宝」按钮**：先只做扫码
- **推荐档位标记**
- **限制只能给自己下单**：别人用你的 ID 下单最多占掉你当天的下单次数，付款成功就清零，不值得为它另开路由
