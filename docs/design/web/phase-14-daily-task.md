# 批次 14：每日任务与 30 天历史

> 状态：已完成。页面与入口见 [docs/web/README.md](../../web/README.md) 第 3 节，素材来源见同文第 4 节「图片素材」，接口与归属校验见 [docs/api/README.md](../../api/README.md) 的「路由与认证」。

每日任务原本只在游戏内有界面。这一批把它搬到网站：`/profile/<steamId>/daily-task` 显示今天的任务、刷新入口与 30 天记录。

## 决定

- **今天与历史来自同一条 `GET /daily-task/{steamId}`**：两块数据在一个响应里，拆成两次请求只会多一个加载态
- **刷新单开一条 `POST /daily-task/{steamId}/refresh`**：guard 只比对路由上的 `:steamId`，给收 body 的旧路由补 `@AllowWeb()` 等于放任何人刷别人的任务
- **刷新按钮不显示剩余次数**：每轮只能刷一次，一个数字只会在 1 和 0 之间跳，不如用按钮自己的状态（刷新任务 / 刷新中 / 已刷新）表达；文案取值与游戏内同一套
- **今天那块里当前轮次排在已完成之上**：玩家打开页面是想知道这一局该做什么，已完成的是结果、不是待办
- **历史用列表，跳过的日子不出现，跨月不插分隔**：日期本来就不连续，日历会把「没打游戏」和「打了但没完成」画成同一个空格
- **一天留三个位置，空位不压缩**：条数不等于轮数，按实际条数排版会让「完成 1 条」和「完成 3 条」的两天看起来一样满
- **历史与已完成的槽位只写图标、星级、指标短名，不写数值**：与游戏内的历史记录一致，带目标值的完整文案只出现在当前轮次的三个任务上
- **每天的积分取 `seasonPoint`，不拿三条任务的奖励相加**：任务池变更后查不到定义的条目服务端会丢弃，加出来的数比实际少
- **界面上不解释时区，今天那条只写「今天」**：`dayId` 是 UTC 天号，游戏内也不解释，两边说法一致玩家才不会以为是两套日期
- **英雄头像走 Valve CDN 的小地图头像**：任务池有 127 个英雄，觉醒页只有 39 个，清单与图都不能复用；PSD 整图里没有英雄与格子的对应关系
- **个人主页的入口卡不带标签**：轮次要多发一次每日任务的请求，而那条接口会写库

## 不做

- **不做补完成、不做领取**：任务完成与积分发放都在对局结算时由服务端完成
- **刷新不做二次确认**：额度本身就是上限，再弹一层只是多一次点击
- **网站不表示玩家在游戏内选了哪个候选**：那是对局里的临时状态，随时能改，接口也没有这个字段
- **不给这条请求加浏览器缓存**：与全站「玩家数据不做浏览器缓存」一致，何况它带副作用
- **不做超过 30 天的翻页**：后端只留 30 条
