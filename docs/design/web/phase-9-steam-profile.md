# 批次 9：Steam 昵称头像

> 状态：已完成。长期决策见 [docs/web/README.md](../../web/README.md) 第 6 节与 [docs/api/README.md](../../api/README.md) 的「对外依赖」。

网站只显示 32 位数字 ID，头部账号区在手机上更是只有一个人形图标，玩家认不出那是自己的账号。这一批把 Steam 的昵称和头像取回来显示。

## 决定

- **单开 `GET /player/:steamId/steam-profile`，不并进 `player/:steamId/info`**：`info` 同时服务游戏客户端，那边不需要昵称头像；Steam 慢或超时也不该拖住整个个人主页。路由挂在已有的 `player` 前缀下，不必改 `api/index.ts` 的路径白名单
- **头像图片由浏览器直连 `avatars.steamstatic.com`，接口只给地址**：图片字节不经过我们的服务器，没有流量也没有函数调用。没选代理转发（每张图多一次函数调用，还要为图片流量付费），也没选转存 Cloud Storage（为一张 184px 的图新开一套存储、公开读规则与失效逻辑）
- **头像只返回 184px 那一档**：头部与身份卡在同一个页面出现，共用一个地址浏览器只下载一次；身份卡 56px 在高分屏上正好需要这个尺寸
- **昵称与头像地址缓存进 Firestore，正常 24 小时、查不到 1 小时**：昵称变动不频繁，24 小时足够；负结果也写一条，否则资料查不到的玩家每次刷新都要打一次 Steam
- **Steam 查不到、资料私密或超时一律返回 200 加空字段，不返回 404**：玩家本身是存在的，只是 Steam 资料拿不到；前端照常渲染并退回改动前的纯 ID 形态，不用写失败分支
- **32 位与 64 位的换算收进 `api/src/util/steam-id.ts`**：登录回调本来就有一份反向换算，同一个魔数不留两份。换算只发生在调 Steam 之前和拿到结果之后，接口入参、缓存文档 id、响应体一律只有 32 位
- **头部昵称截断在 160px**：1024 英文那一档实测只剩 268px，是全站最紧的一处，留出的余量给以后新增的导航项。手机与平板本来就不显示昵称，只把 20px 人形图标换成同尺寸头像，那一行的宽度分毫未动
- **身份卡把会员状态与有效期并成一行，空出的第二行放 ID**：卡片高度与改动前一致，底部那行也不用动。多数玩家没有会员，那两行原本就空着，ID 顶上来反而更紧凑

## 不做

- **排行榜不显示昵称**：游戏客户端用 Dota2 官方接口就能拿到，网站的排行榜要显示时再单独调这个接口
- **不做批量查询**：现在只能查自己，一次一个 ID 够用
- **除新增的这条接口外，现有接口一概不动**

## 后续事项

- 个人主页开放公开查看、或排行榜要显示昵称时，要给路由加一个「允许查别人」的显式装饰器——`auth.guard.ts` 对所有带 `:steamId` 的路由统一做归属校验，不能靠把参数挪到 query 绕开；同时补一个批量方法，`GetPlayerSummaries` 一次收 100 个 ID
