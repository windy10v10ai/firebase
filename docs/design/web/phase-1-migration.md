## 2. 仍然有效的约束

**纯升级的 PR 不改页面，改页面的 PR 不升级。** 混在一起，线上出差异分不清是升级带来的还是重写带来的。这条对后面每一批同样适用。

**`globals.css` 里的 `@apply` 类保留，不删。** 它们是现在唯一把颜色收敛好的地方，删掉等于把颜色散回 JSX。要收拾的是 JSX 里散着的硬编码颜色类。

**设计 token 的角色划分**（取值等视觉风格那一批再改，角色不动）：

| token | 角色 |
|------|------|
| `surface` / `panel` | 页面底色 / 面板与浮层底色 |
| `line` | 边框与分隔线 |
| `control` / `control-hover` | 按钮底色与悬停态 |
| `heading` / `content` / `muted` | 标题 / 正文 / 次要文字 |
| `accent` / `accent-hover` | 强调文字与链接 |
| `accent-solid` / `accent-solid-hover` | 实心强调按钮 |

`line` 和 `control` 当前同值但角色不同，不合并——重设计时边框和按钮底必然要分开走。

## 3. 本批次拍板的技术选择

| 选择 | 结论 | 理由 |
|------|------|------|
| 数据层 | **批次 1 不引入** TanStack Query | 全站只有一个 POST，没有缓存和失效需求。属性页是它真正的用武之地，到那时再定 |
| 表单库 | **不引入** react-hook-form / zod | 全站一个表单，三条规则，自建几十行够用 |
| 图标库 | **引入 lucide-react** | 按需引入，每个图标几百字节；图标用 `stroke="currentColor"`，Tailwind 文字颜色类直接生效 |
| 测试框架 | **不引入** | `web/` 零测试，页面少，浏览器实测比搭一套 runner 划算。校验规则抽成纯函数 |
| 浏览器门槛 | **接受 Tailwind 4 的要求**（Safari 16.4+ / Chrome 111+ / Firefox 128+） | 玩家从游戏内跳到自己的浏览器打开，不经过 Dota2 内置的 CEF |
