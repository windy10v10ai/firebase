# 批次 11：可点击元素与玩家页细节

> 状态：已完成，与批次 12 同一个 PR 实现。可点击元素的长期规范见 [docs/web/design-system.md](../../web/design-system.md)「可点击元素」，本文只留取舍过程。

三件事都围绕同一个问题：**玩家分不清哪里能点**。

## 1. 属性页等级框：由框本身表达「能点」

「勇士等级」「会员等级」两个框是跳个人主页的链接，外观却和旁边不能点的「可用 / 总数」框一样，只靠说明句末尾的「点等级看明细。」提示。改成框右侧加箭头、悬停有反馈，说明句删掉。

- **悬停描边跟货币色走**：勇士框紫边、会员框金边，不用通用的 `card-hover`，免得金色数值的框悬停变成别的颜色
- **悬停比首页卡片多动一层底色和箭头**：这两个框嵌在卡片里、本身是控件底色加细灰边，只变描边在深色底上看不出。首页卡片面积大，只变描边已经够，不跟着改

## 2. 按钮没有手型光标

**是疏忽，不是特意的。** Tailwind 4 的 preflight 不再给 `<button>` 手型（Tailwind 3 给），`<a>` 的手型由浏览器默认提供，于是凡是按钮做的控件（汉堡按钮、语言切换、退出、属性页加减与升级等）都是箭头。此前的设计从没讨论过光标。

**在 `globals.css` base 层统一补**，不在调用点逐个写：新写的按钮不用记得加，禁用态的光标也一并统一。属性卡进度条格子与生效徽章保留问号光标，那里悬停是看说明，不是点击。

排查时顺带修掉的同类问题：不能点的入口带着箭头；整行链接因子元素各自写了文字颜色，悬停看不出变化；入口卡悬停描边深浅不一。对应的规则已写进 design-system.md 与 `web/CLAUDE.md`「可点击元素」。

## 3. 个人主页：会员状态并入身份卡，身份卡与等级卡同一行

原布局左栏放身份卡和会员状态卡，左栏内容少、下半截空着；会员状态单独一张卡只有两行字加一个按钮。

**会员状态并进身份卡**，写法照首页玩家卡；金色「前往订阅」按钮换成文字链接——会员状态在这里只做陈述，不需要与页面主操作同等分量的金色按钮。

**布局采用方案 B**：身份卡占一列、原等级卡占两列同一行，等级卡不拆。未采用的方案 A 是把等级卡拆成勇士、会员两张，与身份卡三张等宽；它更贴合「电脑 3 列」，但要拆卡，还要删掉等级卡里的「可用属性点」一行，改动更大。
