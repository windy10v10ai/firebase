# 启动器内嵌网站

> 已确认的设计方向，尚未实现。首版验证范围见 [网页与登录设计](../design/launcher-web/phase-1-browser-login.md)。

## 玩家体验与技术选择

启动器内打开现有 `windy10v10ai.com`，玩家通过 Steam 官方页面登录后，使用网站的战绩、加点和觉醒功能。复用网站页面与后端鉴权，避免维护两份账号养成界面；网页仍由 GCP 提供，本功能不依赖注册新域名。

Windows 使用 WebView2 承载页面，依靠现代浏览器内核支持现有网站。启动器负责检测 WebView2 Runtime 并处理缺失情况；接入官方 .NET 控件需要调整当前运行要求，不能继续承诺只依赖 .NET Framework 4。具体构建与安装方式由原型验证后确定。

网页加速只覆盖内嵌浏览器中的本站及 Steam 登录所需请求，不修改系统代理，也不承担 Steam 客户端、游戏与游戏下载加速。第三方支付等站外链接需要明确处理，不能默认纳入代理范围。

## 网络与选路

内嵌浏览器直连现有网站和 Steam；直连失败时，通过候选网页代理访问相同的 HTTPS 地址。代理改变网络出口，不改变页面 origin，因此继续使用现有同源 API、Steam 回调白名单和 Firebase Auth 转发。

- **按可达性选路，不按国籍或所在地强制加速**：海外及能够直连的国内玩家不必绕路。
- **本站与 Steam 分别选路**：本站可用、Steam 不可用时，只代理 Steam 登录相关请求。登录关联域名作为整体处理，避免登录中途出口混用。
- **直连优先，失败才测候选代理**：网页按 HTTPS 响应及预期内容检查，不能用游戏 UDP 延迟或端口可达替代页面可用性；完整登录仍以浏览器实测为准。
- **登录期间固定 Steam 出口**：配置刷新和后台探测不切换正在登录的线路，失败后由玩家重试；其他涉及数据修改的请求不因换线自动重放。
- **缓存可用配置和探测结果**：网络变化或连续失败后重新检查，减少重复等待；配置获取失败仍允许尝试直连。

代理节点通过现有启动器 API 的直连与国内备用入口获取，不能依赖尚未取得的网页代理启动。复用游戏中转的配置下发、优先级、停用和回退思路；网页代理与游戏中转分别列出，使用各自的协议和探测结果。节点地址不是秘密，不把长期代理密码放进启动器或公开配置。

国内普通云服务器不作为 Steam 登录的可靠出口。香港和新加坡是海外代理候选，最终按实际网页与登录测试选择；地理距离不能替代整条路径质量。现有游戏中转机器可承载独立的网页代理服务，但 UDP 中转程序与 API 转发服务不能直接承担浏览器 HTTPS 隧道。

## 登录、缓存与权限

Steam 账号登录在官方 HTTPS 页面完成，网站后端核验 OpenID 后签发 Firebase Custom Token，由网页 Firebase SDK 登录和续期。启动器读取到的本机 Steam ID 不代替网站身份验证，网站原有权限校验继续生效。

内嵌浏览器使用固定、当前系统用户可写的数据目录，保存 Cookie、IndexedDB、本地存储和资源缓存。路径与启动器版本、下载位置和代理节点无关，重启、升级或换线不主动清空，避免玩家反复登录。数据与系统浏览器独立，也不上传到代理服务器。

资源缓存服从网站缓存规则；缓存清理与退出登录分开，普通清理不删除登录数据。网站登录仍可能过期或被撤销，不能把本地持久化理解成永久登录。提供清除全部站点数据的入口，供玩家移除 Steam 与网站会话。

代理使用加密连接接入，通过 HTTPS 隧道转发目标连接，不安装根证书、不解密 Steam HTTPS、不采集密码或会话凭据。登录窗口展示实际域名和加速状态，外部页面不获得启动器本机操作权限。

代理只放行本站和经验证的 Steam 登录依赖，服务端执行目标域名与端口限制、拒绝内网目标，并设置访问授权、限流与流量上限。授权在网站登录前可获得，避免登录依赖加速、加速又依赖登录；公开领取的短期凭据不能单独作为防滥用保障。访问日志不记录 Cookie、Authorization 或完整登录回调参数。

Steam 显示的登录地点可能是代理出口，玩家需要核对本人操作后完成 Steam Guard 验证。保持本地数据和稳定出口可以减少不必要的重复验证，但不保证免验证码或登录风控；电脑端代理不能保证手机 Steam 确认也能连通。

## 平台边界

先用 Windows 原型验证完整链路，Mac 内嵌浏览器与按域名代理能力单独验证。正式实现的平台范围和发布顺序尚未确定；不能将 Windows 原型成功视为 Mac 已支持，正式发布需遵循启动器的平台功能约定。
