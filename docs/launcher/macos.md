# 实验性 Mac 房主启动器

Mac 版提供 Apple Silicon 本机开房，让 Windows 启动器使用房间码加入。它是独立的实验实现，Windows 正式版的下载、更新与发布流程保持独立。使用方式与构建入口见 [Mac README](../../launcher/macos/README.md)，验证范围见[测试报告](../../launcher/macos/TEST-REPORT.md)。

## 组成与生命周期

AppKit 窗口通过 JSON 消息控制自带的 ARM64 .NET 网络服务。网络服务复用上游房间 API、STUN、中转协议与本机转发，避免引入第二套联机协议。游戏客户端和专用服分别运行，客户端只连接本机转发端口。

专用服使用独立的隐藏应用身份，避免与前台 Dota 共用应用身份而产生空白 Dock 项或启动冲突。可执行文件在运行时从本机游戏安装复制到临时目录，资源链接回原安装；不修改安装的游戏可执行文件，不随应用分发 Valve 游戏文件。关闭房间清理本应用创建的服务与临时文件，客户端独立保留。

地图从 Steam 创意工坊更新，在游戏插件目录临时挂载；正常关闭后删除挂载或恢复原文件。更新辅助程序调用已安装 Dota 的 Intel Steam API，通过 Rosetta 运行，完成后退出以释放 Steam 游戏会话。

## 客户端启动与认证

Mac 版以安装目录内官方 `dota.sh` 启动客户端，由当前 Steam 会话完成 SteamAPI 认证；客户端已开着时复用。等待主菜单和默认场景完成，再由 LaunchServices 将 `steam://connect` 交给 Steam，减少冷启动时同时加载自定义地图的压力。日志重定向到文件，使客户端不会依赖启动器输出管道存活。

这与 Windows 版通过 Steam 程序启动游戏、直接将连接 URL 交给 Steam 的策略不同。Mac 使用系统注册的 URL 处理器；游戏脚本启动不等同于 Windows 的 Steam 启动策略。当前验证只覆盖启动与连接，退出后切换游廊及 VAC/反作弊兼容性仍需验证，不能据此宣称反作弊安全。

## 状态与故障处理

玩家进入状态以专用服记录的认证账号和完整 signon 为依据，断线时撤销。收到连接请求或添加玩家日志都不足以证明已进图。

服务器采用有限的消息处理预算来容纳 Rosetta 加载尖峰，不关闭处理限制，不写入全局游戏配置。客户端加载参数属于实验调优，单项效果未经隔离验证；资源引擎加载上限仍是已知风险，启动成功不代表长时间稳定性已通过。

## 数据与许可

房间服务接收 Steam account ID、地图版本、网络候选地址及必要房间和线路信息；不读取或发送 Steam 密码与登录令牌。本机日志可能含玩家 Steam ID，分享前需检查。
