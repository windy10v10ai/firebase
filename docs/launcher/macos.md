# Mac 启动器

Mac 与 Windows 是同一个启动器的两个平台，共用联机核心、版本定义、API 地址和中英俄文案。构建与离线测试见 [Mac README](../../launcher/macos/README.md)。官方构建发布工作流验证由 [#1598](https://github.com/windy10v10ai/firebase/issues/1598) 跟踪，官网画面修改与正式发布由 [#1599](https://github.com/windy10v10ai/firebase/issues/1599) 跟踪。

## 界面

Mac 与 Windows 共用横幅、深色配色与橙色强调色，单人、开房、加入采用相同的功能分组。Mac 保留 AppKit 原生输入、表格、菜单和键盘操作；窗口内容可滚动，让长文案与展开的日志仍能访问。

## 平台边界

AppKit 窗口通过 JSON 消息控制自带 ARM64 .NET 运行时的服务。房间、网络、隧道、名单和 HTTP 直接编译 `launcher/core`；账号识别和 socket 系统差异由 Mac 的 `Platform` 实现。界面、游戏启动、专用服进程和地图更新留在平台层。

共通会话、平台执行与界面的三层职责见 [启动器 README](../../launcher/README.md#代码结构)。Mac 的消息桥适配 AppKit 操作和会话状态，平台执行层处理游戏进程与文件操作。

房主运行专用服；加入者只建立到房主的隧道，不启动本机专用服。关闭或离开房间释放本应用的连接和地图挂载，保留游戏客户端。

专用服使用独立的隐藏应用身份，避免前台游戏与专用服的应用身份冲突。可执行文件从本机安装复制到临时目录，资源链接回原安装；不修改原有游戏文件，不分发 Valve 游戏文件。

地图更新辅助程序加载游戏自带的 Intel Steam API，需要 Rosetta。辅助进程完成后退出，释放 Steam 游戏会话。

## 客户端启动

冷启动交给 Steam 程序启动游戏，无法启动 Steam 程序时使用 Steam URL。客户端已开着时通过 `steam://connect` 连接，避免重复启动。冷启动等待主菜单完成再连接，避免同时加载主菜单和自定义地图。

通过 Steam 启动是统一的平台约定；是否能在游戏结束后保持客户端运行并从游廊开局，必须实机验证，不以进图成功替代。

## 状态与许可

房间状态和名单由房主经共用隧道传递，连接成功不代表客户端已进图。房主通过专用服的账号认证和完整 signon 确认进入；自动进入下一局只在客户端开着时执行。

房间服务接收账号、地图版本和必要网络信息，不读取 Steam 密码或登录令牌。日志可能包含 Steam ID。
