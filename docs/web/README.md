# 网站架构

> 背景：[本地主机策略](https://github.com/windy10v10ai/game/blob/develop/docs/design/local-host/README.md) 把加点、洗点、觉醒等账号养成操作迁到网站，玩家用 Steam 登录后操作。本文是网站长期有效的架构、鉴权、页面与菜单、技术方向，只在决策变更时更新。

## 一句话结论

**网站只做展示和调用，所有数据操作都走现有 NestJS API；用户身份用 Steam OpenID 换 Firebase ID Token，API 按 token 里的 steamId 做归属校验；前端按游戏界面风格用 Tailwind 重做。**

## 1. 总体架构

```
浏览器（React 页面 + Firebase JS SDK）
  │  Steam OpenID 登录跳转 / 回调
  │  ID Token 放在 Authorization 头
  ▼
NestJS API（Cloud Functions，AuthGuard 验 ID Token 或 API key）
  │
  ▼
Firestore
```

- **Next.js** 只负责出页面。用户相关页面是静态外壳，数据由浏览器登录后调 API 获取。服务端只读一个 uid 提示 cookie 决定首屏渲染哪套形态，不碰用户数据，见第 5 节「加载态」。
- **App Hosting** 的 Node 版本在各后端的设置页管理，必须与 `web/package.json` 的版本约束一致。
- **NestJS API** 是唯一的数据入口。游戏客户端和网站调同一套接口，差别只在鉴权方式。
- **Firebase Auth** 只用来签发和续期 ID Token，网站不直接读写 Firestore。
- **浏览器用相对路径调 API**，由 `web/next.config.ts` 的 rewrite 转发，页面只跟本站域名打交道。理由见 [api-entry/README.md](../design/api-entry/README.md)。

启动器内嵌网站的已确认设计见 [内嵌浏览器与网页加速](../launcher/web-browser.md)（尚未实现）：继续使用本站域名、页面和鉴权，内嵌浏览器按需选择直连或代理。

## 2. 鉴权设计

做法见 [auth.controller.ts](../../api/src/auth/auth.controller.ts) 与 [auth.guard.ts](../../api/src/util/auth/auth.guard.ts)。这里只留结论：

- 玩家在 Steam 的 OpenID 页登录，后端二次核对签名后签发 Firebase Custom Token，浏览器换成 ID Token，之后每次调 API 带在 `Authorization: Bearer` 头里。
- **uid 就是 32 位账号 ID**，与 Firestore 玩家文档 ID 一致，所有归属校验都比这一个值。
- 只有显式声明 `@AllowWeb()` 的路由接受网站来源；路由里的 `:steamId` 必须等于 token 的 uid，由 guard 统一拦。
- 不用 session cookie，也不加网站专用 API key。登录凭据只在 Firebase SDK 手里，门禁只能做在浏览器里。
- **登录后回到原页**：原页地址放进参与 OpenID 签名的 `next` 参数，中途被改过核对会失败；回调页只接受站内路径，跳回时不在历史里留下回调页。
- **回调核对失败时先在本页重试，不回 Steam。** Steam 的回调参数只能核对一次，但请求没到后端时它还没被用掉，原样再交一次就能登录；只有后端明确拒绝才重走 Steam。国内玩家回到本站这一步常被加速器丢请求，所以失败页提示先关加速器再重试，而关掉加速器后 Steam 页又常打不开。
- **`player-uid`、`player-profile` 两个提示 cookie 不是凭据**，只让服务端决定首屏形态、首屏就画出昵称头像。uid 本来就公开出现在地址里，API 只认 ID Token；任何鉴权、跳转、归属判断都不得依据它们。不用服务端会话或 Firebase 的 `browserCookiePersistence`：服务端只需知道渲染哪套形状，不需要凭据。
- **Firebase Auth 的请求走本站域名转发，不直连 Google。** 部分网络到不了 `googleapis.com`，表现是后端已经签发了 token、页面仍然报登录失败。生产代码里那句连模拟器的方法是唯一能改 SDK 请求地址的入口，依赖 SDK 未承诺的内部行为，**升级 firebase 依赖后要把登录全链路重跑一遍**。
- **Steam Web API key 只在 NestJS 服务端**，任何形式都不下发到浏览器；头像图片由浏览器直连 Steam 图床，网站不代理。

## 3. 页面与菜单

### 页面清单

| 路径 | 页面 | 要登录 | 怎么进 |
|------|------|------|------|
| `/` | 首页 | 否 | 头部品牌名 |
| `/membership` | 会员状态、权益与购买（购买要登录） | 否 | 头部菜单「会员订阅」、首页的会员卡 |
| `/profile/<steamId>` | 个人主页 | 否（看别人的不用登录，玩家可关闭公开） | 头部菜单「个人主页」、头部的 ID 控件、排行榜的行、别人分享的链接 |
| `/profile/<steamId>/property` | 属性加点 | 否（加点要本人登录） | 头部菜单「属性加点」、个人主页的入口卡 |
| `/profile/<steamId>/awaken` | 英雄觉醒 | 否（觉醒要本人登录） | 头部菜单「英雄觉醒」、首页与个人主页的入口卡 |
| `/profile/<steamId>/daily-task` | 每日任务与 30 天历史 | 是，只给本人 | 头部菜单「每日任务」、首页与个人主页的入口卡 |
| `/wiki/abilities`、`/wiki/items` | 百科：抽选技能，商店与抽奖里的自定义物品 | 否 | 头部横排与菜单「百科」、首页入口卡；`/wiki` 跳到技能页 |
| `/my/*` | 玩家页面的未登录入口，登录后跳 `/profile/<自己的 id>/*` | — | 菜单在未登录时指向这里 |
| `/regist/afdian`、`/regist/kofi` | 手动激活 | 否 | 从 `/membership` 进 |
| `/leaderboard` | 勇士积分排行榜 | 否（「我的排名」要登录） | 菜单「排行榜」、首页与个人主页的入口卡 |
| `/launch` | 启动游戏与数据生效时机 | 否 | 头部横排与菜单「启动游戏」、页脚、首页首屏的「下载启动器」与启动方式卡、属性与觉醒页的提示条 |
| `/feedback` | 反馈问题与建议 | 否（未登录要填 Dota2 好友 ID） | 菜单「反馈问题 / 建议」、页脚、首页底部卡 |
| `/legal/disclosure` | 商业披露 | 否 | 页脚 |
| `/login/callback` | 登录回调 | — | 不进菜单 |

`/regist` 拼写是错的，但爱发电和 Ko-fi 的帖子里已经贴出去了，不改。

不做「记录」页：后端没有积分流水，要做得新建集合并在每处积分变动加写入，价值不够。

### 路径为什么带 steamId

玩家数据的页面一律是 `/profile/<steamId>/...`，学 Steam 社区：一套页面本人看与别人看两用，地址能分享，路径参数与接口 `/player/:steamId/...` 一一对应。**页面用 URL 里的 id 请求接口，不从登录态里取 uid**，差别只由「是不是本人」决定。

**属性和觉醒各占一个页面，不做成个人主页里的 tab**：游戏内它们本来就是独立面板，内容量也大；玩家多数从游戏内直达，独立 URL 才能深链。游戏内的「前往网站」按钮直接拼 `/profile/<id>/property`。

**`/my/*` 是未登录时的落点**：菜单里的「属性」「觉醒」拼不出 id，`/my/property` 未登录时显示登录面板，登录后跳到自己的页面，也兜住直接访问和书签。跳转只能在浏览器里做：服务端只有提示 cookie、没有凭据。玩家页面自己不写登录判断。

### 菜单

- **页面上线才放菜单项，上线就要有菜单项**：玩家的主入口是游戏内「前往网站」按钮直达功能页，菜单里一个点进去是空白的项会让他以为网站坏了；反过来只有右上角 ID 控件能进的页面等于没有入口。`config/nav.ts` 里 `href` 为 `null` 的项不渲染
- **未登录也显示属性、觉醒**，点进去看到登录面板，有内容，与页面尚未实现是两回事
- **站内项横排在中间、站外项收到分割线之后**，桌面与窄屏共用一套汉堡菜单
- **横排放不下时先缩短标签，不把项藏进菜单**：藏进汉堡菜单等于让一半玩家找不到。横排取短标签、菜单取全名
- **平板横排只放启动游戏、个人主页、任务、会员四项**，属性、觉醒、百科到电脑档才出现；俄语文案最长，所有宽度都只放这四项
- **排行榜与反馈只进菜单**：排行榜只看不改，玩家不会带着要操作的目的来找；反馈不是常来的地方。两者都另有首页卡等入口，横排留给要操作的功能
- **「启动游戏」按数组顺序排，不提到最前**：启动器下载一次就不用再来
- **百科排在横排最后**；栏目名叫「百科 / Wiki」而不是「技能与物品」：英文全称太长，也给以后放别的内容留余地
- **菜单分三组，组名写在组首**：「我的」「游戏」「社区与帮助」，按「是不是跟着自己账号走」分，玩家不用知道页面怎么实现。首页「主要页面」的卡不分组、顺序与菜单一致：按组拆会多出半空的行
- **手机与平板品牌名收成「10v10AI」**：写全名放不下右侧控件
- **已登录时 ID 与退出合成一个控件**，ID 文字到电脑档才出现，平板以下只有图标、退出在菜单底部
- **菜单浮层手机铺满整行，平板起是挂在汉堡按钮下的面板**：宽屏上铺满会让菜单项离按钮太远
- **头部吸顶，实心炭灰；只有首页在顶部时透明**：长页面往下翻也能随时切页；首页首屏压着游戏图，头部透明才和首屏连成一片，一滚动就换回实心，免得文字叠在内容上。其他页面没有大图，透明只会显出一片纯色，所以不做
- **手机与平板的头部控件 44px 高**，电脑档收回 36px：触屏要手指点得准，有鼠标时矮一点更紧凑；菜单行各宽度都不低于 44px
- **不加「跳到正文」链接**：玩家几乎不用键盘逛网站，多一个隐藏链接不值得
- **链接按登录态拼**：已登录指向 `/profile/<uid>/...`，未登录或登录态还在恢复时指向 `/my/...`
- 商业披露这类法务链接放页脚

### 个人主页

| 区块 | 内容 |
|------|------|
| 身份卡 | Steam 昵称与头像、ID、会员状态与有效期、今日签到（本人的会员才有）、点赞举报净值；「会员订阅」文字链接 |
| 等级卡 | 勇士等级、会员等级、累计与可用积分 |
| 功能入口 | 属性、觉醒、每日任务、排行榜四张卡，标签分别显示可用属性点、已觉醒 / 可觉醒、今天完成轮数、名次 |
| 战绩 | 场次、胜率、行为分、生涯击杀死亡助攻等，照搬游戏内战绩页 |
| 近期战绩 | 先列出最近 50 场的单场明细，全部列出不折叠（折叠后玩家找不到展开入口，以为只有 10 场），往下滚动自动加载更早的战绩；点开看这一局剩下的数值 |

- **会员的东西集中在身份卡**：状态、有效期、签到、订阅入口是同一件事的四个面；会员状态只做陈述，订阅入口用文字链接而不是金色按钮
- **入口卡只写标题与标签，不写说明小字**：有用的信息在标签上；标签放标题下方，俄语并排放不下
- **可用属性点只在入口卡上出现一次**，等级卡里不重复
- **Steam 昵称头像、近期战绩、名次各自单独请求**，不并进玩家数据接口：昵称要向 Steam 取，快慢不由我们；近期战绩体量大又在页面最下方；名次要在库里数人数。各自晚到不拖住整页。近期战绩的取舍见 [player-stats-recent](../design/player-stats-recent/README.md)

### 别人看到的个人主页

个人主页、属性、觉醒三页对别人开放，不登录也能看，只读。

- **默认公开**，玩家在身份卡的「公开主页」开关里关掉。关掉后别人只看到「资料未公开」，连昵称头像也不给
- **不给别人看**：会员有效期与已过期状态、签到、累计积分与升级进度、可用积分、行为分、近期战绩、每日任务。有效期与过期状态反映付费经历；行为分与 Dota 一样只给本人；近期战绩能看出玩家什么时候在玩；每日任务的读取会替玩家生成当天任务。字段裁剪在 API 做，见 [docs/api/README.md](../api/README.md) 的「路由与认证」
- **访客版只读**：没有签到、开关与订阅链接，名次并进身份卡、右边换成分享按钮；入口卡只有属性、觉醒；属性页没有加点按钮，觉醒页只列已觉醒的英雄
- **开关与分享放在同一行**：「谁能看」和「发给谁」是一件事
- **本人版与访客版首屏就定下**：只看「当前登录的 uid 是否等于地址里的 id」，uid 首屏取自提示 cookie；不按数据里少了哪个字段判断，否则数据到了才多出或少掉一块

### 链接分享卡片

链接贴进聊天软件时的卡片只靠页面里的 Open Graph 标签。

- **全站一张通用卡片**；公开的个人主页换成玩家卡片：标题「<昵称> 的 10v10 AI 战绩」，描述带场次胜率，配 Steam 头像。第三人称是因为链接谁都能转发；具体数字比泛泛的邀请更想让人点开
- **数据只走匿名读接口**：主页关闭公开时接口本身拒绝，卡片退回通用版，网站不另做公开判断
- **标签页标题不带昵称**：带了 GA 的页面标题报表会按玩家拆散
- **微信、QQ 加进 Next 的爬虫名单**，不加的话元数据被排到 `<body>` 末尾、卡片出不来
- **不做专门生成的分享图**：昵称要整套中文字体才渲染得出，QQ、微信又只显示小方图
- 微信直接粘贴链接不出卡片，在微信里打开再「发送给朋友」才有

### 排行榜

`/leaderboard` 按累计勇士积分列出前若干名，底部贴一条「我的排名」。

- **榜单是每天一份的快照**，昵称头像一并存进快照，网站一次请求画出整张榜。Steam 整体不通时不落库，免得一整天都没有昵称
- **榜单允许浏览器 HTTP 缓存**：一天才变一次、人人看到的一样、玩家也改不了，不受玩家数据不加 HTTP 缓存那条约束
- **「我的排名」贴在列表底部**，滚动时一直看得见；在榜上时点了滚到自己那一行
- **名次分档放进同宽的胶囊**，第 1 名会员金底：靠前的名次都值得标出来，不止前三。**紫色只给「自己」那一行**
- **每一行都能点进对应玩家的个人主页**，行链接不预取：滚动时大量行进出视口，逐行预取等于白发请求

### 百科

技能页收抽选池里的技能；物品页分「商店」「抽奖」两类，用标签与搜索框下面那一行的分段切换来切。

- **默认显示商店**：商店是每局都会逛的地方，抽奖池是固定的一小批
- **两类各看各的，不做「全部」视图**：抽奖档位 T1 最稀有，价格档越往上越贵，放在一个视图里没法排；一件物品两边都有就两边都列
- **商店只收自定义物品**：商店里的，加上材料拿得到、靠配方合成的（配方都能直接买），再加打怪掉落的材料；排除名单写在同步脚本里。原版 Dota 物品不进百科页；game 把高级版与原版对调了名字的（写在原版覆盖文件里、game 本地化另起了名字）算自定义物品
- **商店分三区：装备、消耗道具、掉落合成**。装备按价格分五档，边界与 bot 出装分档一致，价格由配方价加材料价逐层加总；标签写价格区间不写 T 编号，免得和抽奖页的 T1 弄混。同一档里同系列的装备排在一起、按升级顺序，系列名单写在同步脚本里；跨档的升级线仍各在各的价格档。消耗道具与掉落材料单独成区：玩家查它们看的是效果，不是拿价格比
- **搜索两类都查**：搜索时分段切换上带两边的结果数；当前一类一件都没有、另一类有时，空状态里直接给切换按钮
- **格子提示的副标题写分类加档位**：技能写「主动」与 T4，抽奖物品写「抽奖」与 T2，两段分开呈现；商店物品照游戏写金币图标加价格
- **不显示合成关系**：要多一套跳转，弹窗也会变长；价格已经写在副标题里

### 会员页

- **会员和会员积分上下排在同一页**：分成两页，玩家不一定会点到第二页
- **支付宝与 Stripe 要登录**：这两家的订单由我们下，离不开玩家 ID；爱发电、Ko-fi 在自己的网站付款，玩家在留言里填 ID
- **付款方式用标签切换，默认按语言选**：中文支付宝，英文、俄文 Stripe；标签顺序固定为支付宝、爱发电、Stripe、Ko-fi
- **`?platform=<平台>` 指定标签并滚到付款区，不看网站语言**：游戏内的付款按钮靠它直达对应平台；指定的平台记在本标签页，登录回来仍停在那里
- **支付宝与 Stripe 标「推荐」**：付款后自动到账、不用填 ID；电脑档跟在平台名右边，窄屏压在标签右上角
- **点档位就付款**，不做「先选档位再点付款」；只扫码，不做「打开支付宝」按钮
- **Stripe 跳托管收银台，付款结果由网站查单确认**：跳回地址不算到账，查到订单成功才显示已开通，弹窗与支付宝扫码弹窗同一套外形。设计见 [docs/design/stripe-payment/README.md](../design/stripe-payment/README.md)
- **划掉的原价：人民币用爱发电价，美元用 Ko-fi 价**：和游戏里一样，让玩家看出优惠；美元会员标折扣百分比、积分标省多少：会员的省额带零头，积分的正好是整数
- **激活页登录后自动填入 Dota2 ID**，未登录仍可手填，激活接口保持公开

### 反馈

`/feedback` 与启动器、游戏内共用同一个接口、同一套类型和「相关内容」，文案也照搬启动器。

- **不登录也能发**：登录本身出问题的玩家最需要反馈
- **未登录要填 Dota2 好友 ID**：API 看到的都是网站的转发地址，按 IP 限频会让所有未登录玩家共用一份额度，按 ID 计才互不挤占。填的 ID 记为未验证
- **不附日志，描述必填**：网站不带日志与游戏现场，没有描述就没有可查的信息；游戏里的问题引导玩家用启动器反馈
- **出错的页面带着现场跳进来**：网址参数预填相关内容、ID 与描述，登录失败页用它带上诊断块

### 其他页面决定

- **每日任务历史网站显示全部 30 天**：从游廊开局时游戏内受代发通道容量限制只回几天，网站没有这个限制
- **网站签到与游戏内开局签到共用同一份签到状态**，两个入口不会重复发放
- **网站不显示快照截至日期**：要后端先把导出时间吐出来，收益只是把「下次地图更新后生效」说得更具体
- **标签页标题是「页面名 | Windy10v10AI」**，页面名跟当前语言走、品牌名不翻译；GA 要合并看时按网页路径统计，不为报表牺牲玩家看到的标题
- **搜索引擎只收录陌生人能直接看完整内容的页面**：`/my`、`/login`、`/feedback`、`/profile/*` 带 noindex（个人主页公开是为了分享，没同意被搜到）；不用 `robots.txt` 屏蔽，已收录的页面要让爬虫读到 noindex 才会移除。`/regist/*` 要能被搜到

## 4. 开局方式与命名

从游廊开局时，游戏服务端的请求由玩家的游戏客户端代发（做法见 game 仓库的 `src/vscripts/api/README.md`），所以平时就是在线的；代发偶尔会失败，这局就退回地图更新时导出的数据，也就是离线。

用启动器开局：玩家从 `/launch` 下载 `Windy10v10AI.exe`，它在玩家电脑上单独开一个 Dota 服务器再连进去，服务器逻辑和游戏画面分到不同核心，10v10 后期不再卡顿；这局直连 API，也能开房间让朋友加入。源码在 [launcher/](../../launcher/)。控制台命令作为不想下载软件的玩家的备选，放在下载区下方默认折叠，标「仅单人」。

**命名按三个维度分开，不合成一个词**，取值与文案规则见[根目录 CLAUDE.md](../../.claude/CLAUDE.md) 的「用语」。不拿「在线 / 离线」当动作名，是因为连接状态和开局方式不是一一对应的：游廊开局平时在线、偶尔离线，启动器开局也是在线。动作名按「怎么开始」命名，将来再多一种开局方式只要在对比表里加一列，入口文案不用改。

- **叫「启动器」，不叫「专用启动器」**：「专用」会让玩家联想到专用服务器
- **生效时机只说「下一局生效」**：两种方式平时都在线，分开说只会让玩家以为有差别
- **完整规则只在 `/launch` 讲一遍**，其余页面放一句提示加链接：分散各写一套，改一次口径要追七八处，迟早互相打架
- **不对玩家列游戏内暂缺的功能**：那些在陆续补齐，写进文案就得跟着改一轮

`/launch` 页按「先讲差别、再给下载」排：对比表在最上面，第一行是多人联机（两列都支持，让玩家一眼看到启动器也能联机）；下载区在中间；最后是启动器的更新日志。

- **对比表两列叫「游廊 / 启动器」，只在启动器列配「推荐」徽章**：两种方式都能联机，没有一句话能概括各自适合的场景
- **表里只用三种符号**：绿色 ✓ 支持，正文色三角有时不行，红色 × 不支持。三角不用警示色：偶尔连不上不是大问题，染成橙色会让玩家以为这条路不能走
- **下载区按系统切换，Windows 与 Mac 各一个 tab**：两个系统的拦截提示完全不同，分开写才讲得准。默认选中玩家当前的系统，认不出按 Windows；手机和平板提示改用电脑下载。Mac 版的官方包放进 `public/downloads/` 之前不出现 Mac tab
- **先给下载，分隔线下面才写说明与两步「遇到什么、怎么做」**：启动器没有代码签名，Windows 浏览器下载与第一次运行会各拦一次；Mac 要拖进「应用程序」，第一次打开再放行一次。每步配中性色简图，不仿真弹窗，Mac 安装图照 DMG 窗口的实际样子画。Mac 分两段、说明在上图在下：先拖进「应用程序」并在弹窗点「完成」（不是「移到废纸篓」，点错应用会被删掉），再到系统设置搜「安全」、滚到最底部点「仍要打开」；「更多信息」这类一行小字最容易漏看，用高亮框和序号标出，标记用主色标记档的橙
- **「代码已开源」与「隐私与安全说明」放卡片底部，两个系统共用**：它们不随系统变化，放在步骤后面当通用备注
- **安装包随官网部署**，放 `public/downloads/`：玩家本来就要上官网，官网打得开下载就能用；GitHub Release、Firebase Storage 国内常打不开。服务器上的文件名带版本号并永久缓存，玩家存下来的名字固定。Windows 提供 exe；Mac 官网入口给 DMG（拖进「应用程序」安装），ZIP 只给应用内更新用，页面不露出

## 5. 前端技术方向

| 项目 | 方向 |
|------|------|
| 样式 | Tailwind 4 + CSS 变量定义设计 token，配色、按钮见 [design-system.md](design-system.md)。浏览器门槛随 Tailwind 4：玩家在自己的浏览器里打开，不经过 Dota 内置浏览器 |
| 组件 | 自建 Button、Input、Field、Skeleton、Card 等一小套，不引组件库 |
| 字体 | 正文用系统字体；顶栏与页面大标题用只截了这些字的 Noto Sans SC，预加载。整套中文网页字体要按需下载上百个分片，首次访问来不及，同一个人前后会看到两种字体；接口数据收不全，用系统字体避免一行里混两种字形 |
| 数据层 | TanStack Query，缓存只在内存，见下文「数据缓存」 |
| 登录状态 | `AuthProvider` 包住 Firebase SDK，初始值来自提示 cookie；只有已登录 / 未登录两态，没有加载中 |

### 页面宽度与屏幕档位

**外框统一 `max-w-7xl`，宽度跟着屏幕连续变化**，头部与宽页正文左右对齐。不用 Tailwind 的 `container`：它按断点跳档，屏幕落在两个断点之间时右侧空出一截。页面按内容类型在外框里再收窄成宽、中、窄、提示四档。

全站按三档设备排版：手机、平板、电脑。

- **平板按触控设备对待**：较矮的按钮、常驻的次要按钮、完整的账号文字到电脑档才出现；平板比手机多的只是宽度
- **不设 640 这一档**：没有对应的主流设备，按它切换的布局没人看得到
- **成排的条目卡手机 1 列、平板 2 列、电脑 3 列**，单卡宽度在宽屏上不被拉长；觉醒页那种图墙另按自己的尺寸定列数，仍然只用三档

### 多语言

**网站标准支持中文、英文、俄语三种语言**，每条界面文案三种同时交付，浏览器验证与 PR 截图三种都过。与 game 侧本地化的三份对齐；俄语文案最长，版面按它来量。

- **界面语言按「cookie → 浏览器 `Accept-Language` → 英文」确定**，选择存 cookie 不进 URL
- **没译到的 key 回落英文**，只用于接入新语言的过渡期：可以只译一部分就上线，缺的位置出英文而不是空白
- **语言控件是图标加书写体系标记**（文 / A / Я），不用国旗；列表里语言名用它自己的写法，看不懂当前界面的人才最需要这份列表
- **英雄名与技能说明不走消息文件**，从 game 仓库的本地化文件同步进网站配置，缺俄文的条目落英文

### 图片素材

**Dota 自带的图从 Valve 的 CDN 取，落盘成带内容 hash 的文件，不引外链。** 取图脚本在 `web/scripts/` 下，一类素材一份清单，清单进 git，页面只认清单里的文件名；带 hash 的文件永久缓存。

- **英雄头像用小地图头像，不裁 game 仓库的 `minimap_hero_sheet` 整图**：那张图里没有英雄与格子的对应关系
- **物品与技能图标一类一个目录、按内部名索引**，战绩出装与百科查同一份清单
- **图先取 game 仓库、再取 Dota CDN**：自定义物品和换了贴图的技能只在 game 仓库里有；都取不到的留空、页面画灰格
- **物品收录范围是「能留在物品栏里的」**，并上 GA 导出的玩家购买记录：原版升级件走引擎自带的配方，game 配置推不出来。技能收抽选池里的全部
- **名字先读 game 的 addon 本地化，再读 Dota 官方数据接口**，不依赖要手工解包的文件
- **界面自己的图标用 lucide**，只有游戏里的东西才取 Dota 的图

### 技能提示框

**觉醒页、百科与近期战绩共用一套技能块**：内容和顺序照游戏内的提示框，外观用网站自己的中性色，数据由同步脚本从 game 仓库生成。见 [ability-tooltip.md](ability-tooltip.md)。

- **近期战绩里的主要原版装备、中立物品与中立被动也能点开说明**，与百科共用悬浮提示与详情弹窗。战绩专用名单和说明独立成包，百科页不加载；说明在首次交互时按来源加载。普通物品保留成装、功能装备和主要特殊物品，基础配件与配方只显示名字；中立物品包括死亡后的退化形态，已移除的物品不收录。
- **说明数据与名单分开**：名单小，战绩页随页面带上，用来判断哪格能点；说明包在第一次悬停或点开时才加载，个人主页不因它变重

### 渲染方式

| 页面 | 方式 | 原因 |
|------|------|------|
| 首页、商业披露、会员、激活页外壳 | 构建时静态生成 | 没有用户数据，最快，可被搜索 |
| 个人主页、属性、觉醒、排行榜 | 静态外壳 + 浏览器调 API | 数据按访问者裁剪或每天变；个人主页的分享卡片由服务端出 metadata |
| 百科 | 构建时静态生成；提示框的说明另成静态包按需加载 | 公开、要被搜索；说明全量太重，单独成包后浏览器长期缓存 |

根布局要读 cookie 和请求头，所有页面实际都按请求动态渲染，每次渲染都是一次函数调用。所以**页头、页脚的链接关掉预取**，否则函数调用量随页面浏览量成倍放大；正文里的链接照常预取。

### 加载态

页面一出现就是最终结构，之后只有数值在变，布局不动。**渲染哪套形态**由服务端读提示 cookie 决定，Firebase 恢复完成后只做校正——登录凭据在浏览器的 IndexedDB 里，SDK 还要联网校验一次才给结论，不绕开就只能先按未登录渲染；**格子里的内容**没到时由容器留出位置。规约见 [web/CLAUDE.md](../../web/CLAUDE.md)「加载态」。

### 数据缓存

站内来回跳转时，去过的页面直接显示，没过期就不重新请求。缓存只在浏览器内存里，刷新即清空。

| 档位 | 数据 | 理由 |
|---|---|---|
| 实时：进页面必请求，离开即丢弃 | 属性加点、觉醒、会员（含付款）、每日任务 | 玩家来这些页面是为了操作，看到旧值可能按错 |
| 短缓存 | 玩家数据、近期战绩、每日任务入口卡的完成数 | 主要用来看，一局游戏结束或网站上操作后会变 |
| 长缓存 | 雷达图、我的名次、Steam 昵称头像、排行榜 | 变化慢或全体共用 |

- **过期后先显示旧数据、同时后台请求**，回来后原地替换；切回窗口时只刷新已过期的。每日任务例外：它的读取会顺带写库，切回窗口不请求
- **写操作后只让「玩家状态」过期**：玩家数据、属性、觉醒、会员会被网站上的操作改变；战绩、名次、昵称头像网站上改不了，不跟着过期
- **换账号、退出登录时清空全部缓存**：公用电脑上不该把上一个人的数据留给下一个人
- **不存 localStorage**：刷新后先显示旧值再跳成新值，会让人以为看错了
- **玩家数据不加 HTTP 缓存**：浏览器的 HTTP 缓存清不掉，操作后会看到旧值
- 选 TanStack Query 而不是 SWR：按 key 前缀批量失效、离开即丢弃在 TanStack 里各是一行配置

规约见 [web/CLAUDE.md](../../web/CLAUDE.md)「数据请求与缓存」。

## 6. 统计

**网页与游戏共用一个 GA4 媒体资源，各自一条数据流：浏览器只发浏览行为，改数据的动作一律由 API 在服务端发。**

- **媒体资源共用**：两边的 user_id 都是 32 位账号 ID，同一个玩家在游戏里和网站上才认得出是同一个人，BigQuery 导出也落在同一个数据集
- **数据流分开**：网页的会话由 gtag 自动产生，游戏侧的 `session_id` 是自造的「账号-对局」，混在一条流里会话数与互动时长都没法读
- **数据流由 Firebase 自动建**，dev 与生产各一条，测量 ID 写进 `web/.env` 与 `web/.env.development`。部署出来的 dev 后端连的是生产环境，事件进生产流是对的；哪天要分开，在 `web/apphosting.dev.yaml` 覆盖测量 ID
- **浏览器侧用 gtag，不用 `firebase/analytics`**：后者初始化要多取一次远端配置，等于多一个可能到不了的域名
- **谁发什么按浏览器在不在场分**：改数据的动作（加点、洗点、觉醒、签到、结算、购买）由 API 发，同一件事不在两边各发一次。服务端事件带 `server_type`，见 [docs/api/README.md](../api/README.md) 的「路由与认证」
- **登录之前的浏览不会回填给 user_id**，落地页到登录的漏斗只能在设备 ID 维度看
- **不代理 gtag**：代理会把来源 IP 变成服务器、地理维度失真。网页统计因此缺大陆用户，玩家分布以游戏侧数据为准，网页统计只看趋势与相对值
